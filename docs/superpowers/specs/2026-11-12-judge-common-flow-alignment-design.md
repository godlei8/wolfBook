# 引擎对齐通用流程（设计稿，2026-11-12）

规则依据：`docs/judge/house-rules/00-通用流程.md`。它末尾「和引擎现状不同」列了四处，这份设计稿说每一处怎么改。只动新流程房间，旧流程房间（`auto_judge_enabled = 0`）行为不变。

基线：改之前后端 456 个测试全部通过（含另一个会话还没提交的狼人「确定」改动）。

**状态（2026-11-12）**：五项都已实现，后端 492 个测试、小程序 147 个、后台 35 个单测全部通过；实时联调脚本 `judge-e2e.mjs` 还没重跑。实现时多了一处：遗言开始时把原来的公告（死讯、自爆、开枪）记在这条待办上，遗言结束后恢复，免得「请 X 号留遗言」盖掉死讯。

## 1. 狼人刀口：没统一算空刀

**规则**：狼人那一步结束时，所有存活的狼人选的是同一个目标才算数；没统一算空刀。

**现状**：`NightResolver.tallyKnife` 按票数取多数，平票随机。

**改法**：

- `tallyKnife(picks)` 改成：选的全是同一个座位，返回这个座位；否则返回空（空刀）。不再需要随机数。
- 有狼明确选了空刀、其他狼选了人：不统一，空刀。
- 带刀的机械狼人独自在这一步：他选谁就是谁，不变。
- `JudgeService` 关狼人那一步时调用它的地方（存 `phase_data.knifeSeat`）跟着改签名，别的不动。

**用户已定（2026-11-12）**：到点还有狼没选时，没选的狼不算在内，选了的狼一致就成立（控刀）；一个都没选才空刀。

**测试**（`NightResolverTests`，先写先看它失败）：全员同一目标 → 该目标；两个目标各有人选 → 空刀；有人选空刀有人选人 → 空刀；都没选 → 空刀；有人没选、其余一致 → 按上面拍板的结果。集成测试里原来靠「多数」出刀口的用例改成全员同一目标。

## 2. 发言完自动进入放逐投票

**规则**：所有存活玩家发完言，自动进入放逐投票。

**现状**：最后一位发完后停在 `day_speech`，要房主点「发起投票」（`advance: start_vote`）。

**改法**：

- `nextSpeaker` 里，白天发言（不是警上发言）切过最后一位时，直接做 `start_vote` 现在做的事：进 `exile_vote`、起 30 秒投票计时、写公告。
- 发言计时照旧「到点只提示、不强制换人」，所以最后一位要自己点「结束发言」，或者房主点「跳过这位」，才会进投票。
- 小程序房主操作栏（`utils/judge/day.js` 的 `hostActions`）在 `day_speech` 去掉「发起投票」，只留「跳过这位」。
- 后端 `start_vote` 这个动作保留不删：线上旧版小程序的房主手里还有这个按钮。
- 警上发言结束后的「开始警长投票」不在这次范围，仍由房主点。

**测试**：`JudgeFlowIntegrationTests` 加「最后一位结束发言后直接是投票阶段、有投票截止时间」；`judge-day.test.mjs` 改房主按钮的断言；联调脚本 `judge-e2e.mjs` 去掉 `start_vote` 那一步。

## 3. 遗言

**规则**（00 第 12 节）：

- 每人 120 秒，自爆的狼 60 秒。
- 第一夜死的人有遗言；白天出局的人都有（被放逐、被开枪带走、自爆）；第二夜起夜里死的没有；被法官点杀的没有。
- 多人同时有遗言，先后随机。
- 顺序：先开枪，再留遗言，最后移交警徽。

**现状**：没有遗言这一步。出局待办队列（`phase_data.pending`）只有技能询问、开枪、移交警徽三种；自爆直接天黑。

**改法**：遗言做成待办队列里的第四种 `last_words`，不新增阶段。

### 3.1 纯规则（新文件 `service/judge/JudgeLastWords.java`，全部单测）

- `seconds(出局方式, 第几天)`：返回这个人的遗言秒数，0 表示没有。
  - 夜里死：第 1 天 120，之后 0。
  - 被放逐、被开枪带走：120。
  - 自爆：60。
  - 被法官点杀：0。
- `arrange(队列, 新出局的人, 随机数)`：把新出局者的待办排进队列，保证整条队列始终是三段：
  1. **技能段**：每人一条技能询问（连锁出局的插在当前这条后面，和现在一样）。
  2. **遗言段**：有遗言的人各一条，新加入的随机插进还没开始的遗言里。
  3. **警徽段**：出局的警长一条。

  这样无论连锁多深，都是所有技能处理完 → 遗言（随机先后）→ 移交警徽。

### 3.2 编排（`JudgeService`）

- `startPending` 和开枪连锁那两处改成调 `arrange`，调用方传「出局方式」。
- **每条待办轮到它时才开始计时**。现在所有待办的截止时间在入队时就算好了，两个人同时出局时第二个人只剩第一个人用剩下的时间；有了 120 秒的遗言这个问题必须修。入队只记时长，轮到时再写截止时间。暂停 / 继续的顺延逻辑跟着简化（只顺延当前这一条）。
- **遗言怎么结束**：本人点「结束遗言」；到点自动结束；房主可以点「跳过」（和白天发言的「跳过这位」同一个思路，人离席时不用干等）。
- **谁看得到**：技能询问只发给当事人和法官（不变）；遗言是公开的，所有人的快照里都有「X 号留遗言」和倒计时。
- **公告**：轮到时「请 X 号留遗言」，房主手机播报同一句。
- **自爆**：
  - 白天发言时爆：出局后进待办，60 秒遗言 →（是警长再移交警徽）→ 天黑。
  - 警上发言时爆：和现在一样先公布昨夜死讯，自爆者的 60 秒遗言和昨夜死者的待办排在同一条队列里，处理完停在公布死讯，房主点「天黑」。
  - 最后一只狼自爆：当场结束，没有遗言（对局结束后待办作废，规则已有）。
- 对局结束则剩下的遗言作废，和其他待办一样。

### 3.3 小程序

- `utils/judge/pending.js`：多一种 `last_words`。本人看到「请留遗言」+ 倒计时 +「结束遗言」；其他人看到「X 号留遗言」+ 倒计时；房主多一个「跳过」。
- `utils/judge/voice-cue.js`：遗言轮到时播一次。
- `room.vue` 自爆确认框的文字「没有遗言」改成「有 60 秒遗言」。
- 线上旧版小程序遇到不认识的 `last_words`：当事人看到的是「你出局了 / 确认」，点了等于结束遗言；其他人看到「等待出局玩家确认」。能走完，不卡房间。

### 3.4 测试

- `JudgeLastWordsTests`：每种出局方式和天数的秒数；`arrange` 的三段顺序、连锁、随机先后（固定随机种子）。
- `JudgeFlowIntegrationTests`：第一夜死者有遗言、第二夜死者没有；被放逐有遗言；猎人开枪 → 两人遗言 → 警徽的先后；自爆 60 秒遗言后天黑；点杀没有遗言；遗言到点自动结束；第二条待办轮到时才开始计时；别人看不到技能询问但看得到遗言。
- `judge-pending.test.mjs`、`judge-voice-cue.test.mjs` 补对应用例；联调脚本五局都要能走过遗言。

## 4. 女巫自救

**规则**：全程不可自救。

**现状**：板子专属配置 `witchSelfSave` 可以设成 `first_night`，默认不能自救，现有板子都没开。

**改法**：和「一晚一瓶」一样在 `JudgeRules.withDefaults()` 一处收口，一律不能自救；后台板子编辑页去掉这个开关；AI 助手资料里那一行固定写「女巫不能自救」。数据库里旧值不清，读到也当不能自救。

**测试**：`JudgeRulesTests` 改成「写了 first_night 也按不能自救」；`NightResolverTests` 里首夜自救的用例改成被拒；后台 `board` 单测去掉开关相关断言。

## 4b. 女巫只在还有解药时看到刀口

**规则**：女巫只有还有解药的时候显示刀口，解药用完后不再告知。

**现状**：`buildNightInfo`（`JudgeService` 约 780 行）女巫那一步一律下发 `knifeSeat`。

**改法**：下发 `knifeSeat` 时多一个条件：本人 `status_json.antidote` 不为 false。没解药时 `knifeSeat` 为 null，小程序女巫面板已经按 null 显示「今晚没有刀口信息」类文案，具体文案看 `night-panel.js` 现状再定。法官视角不受影响。

**测试**：`JudgeFlowIntegrationTests` 加「女巫用掉解药后下一晚快照里 `knifeSeat` 为 null，毒药照常可用」。

## 5. 顺序

1 → 2 → 4 → 4b → 3。前四项各自很小、互不相干；遗言最大，放最后。每一项都是先写测试看它失败、再改引擎、再跑全量后端测试，四项都过了再跑一遍联调脚本。
