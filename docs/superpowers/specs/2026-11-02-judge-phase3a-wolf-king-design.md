# 电子法官三期 A：狼王 + 全局规则

状态：设计稿（2026-11-02），待审阅。上游设计：`docs/design/judge-auto-mode.md`（§4.11 机制表、§11 分期）。

## 1. 要做什么、为什么

三期原计划是「扩展技能 + 自建板子」。用户把**自建板子延后**，这一步只做扩展技能，并且先只做两个板子：**「狼王守卫」和「预女猎白」都能无法官全自动跑完一局**。

- 「狼王守卫」线上已有（生产库 `boards.id = 8`，2026-11-02 只读核对）：预言家、女巫、猎人、守卫、黑狼王各 1，狼人 3，平民 4，12 人，屠边。现在卡在黑狼王没有机制，板子只是 `partial`。
- 「预女猎白」（生产库 `boards.id = 2`，和种子一致）二期已经是 `full`，这一步只需保证在全局规则下照常跑。

同时把「各家规则不一样」的地方收成**一套全局规则**：所有板子都按它走，不做成每个板子的开关。用户的原话：「各家规则不一样的时候你可以问我，这个做成全局板子规则」「女巫也改，这些就该做成全局规则，每个板子都这样，同样还有其他常用的角色也一起做了」。

### 目标
- 新增技能机制 `wolf_king`（狼王），图鉴里的「黑狼王」用它。
- 「狼王守卫」的支持级别变成 `full`，可以开无法官局。
- §3 的全局规则写进引擎，替换掉板子级的女巫规则。

### 非目标
- 自建板子（延后）。
- 其他功能角色：白狼王、狼美人、骑士、机械狼、石像鬼、摄梦人、守墓人、魔术师、丘比特等。「狼王摄梦」（id 9）、「狼王魔术师」（id 12）也带黑狼王，做完后仍是 `partial`，因为摄梦人、魔术师还没有机制。
- 部署上线。生产后端还是 2026-10-29 的一期版本（`roles` 表没有 `mechanic` 列），二期也没部署；这一步做完后和二期一起部署，部署前单独问用户。
- 胜负条件（屠边 / 屠城）仍跟板子走：这是板子本身的玩法，不算规则分歧（用户已认可）。

### 反目标（做成这样算失败）
- 公告、对局记录、待办标题、播报里任何一处能看出开枪的是猎人还是狼王。
- 带黑狼王的板子在无法官房间里流程卡住，或狼王被当成没有机制的角色只播报。
- 改女巫规则后，旧房间（`rules_json` 里存了板子级女巫规则）结算出和全局规则不同的结果。

## 2. 已拍板（用户 2026-11-02 确认）

狼王：
1. 夜里被刀死的狼王可以开枪：天亮公布死讯后进出局技能询问，和猎人一样（15 秒询问 + 20 秒选目标）。
2. 被放逐的狼王可以开枪：先开枪，再遗言。
3. 可以带走任何一名活着的玩家，包括狼队友，不能带走自己。
4. 开枪公告只说「X 号发动技能，带走 Y 号」，不说是猎人还是狼王。
5. 被带走的人如果是猎人（没中毒）可以接着开枪，连锁规则不变。
6. 狼队可以自刀狼王，狼王死了照样能开枪。
7. 被毒的狼王不能开枪；被法官点杀的狼王不能开枪。

胜负（用户 2026-11-02 补充）：
8. **双方同时达成算狼人胜**：同一次出局里，最后的狼人出局的同时，神职全部出局或平民全部出局（屠城板子是好人全部出局），判狼人胜。这和二期的「同时达成算好人胜」相反，要改。
9. **胜负一达成就马上结束**，后面的待办不再执行：最后一只狼是狼王、最后一个神职是猎人时，他们出局的那一刻对局就结束，都开不了枪（用户原话「最后的狼王和猎人都开不了枪」）。这是引擎现在的顺序（每次出局先判胜负，判出结果就不进待办），不改。

## 3. 全局规则（所有板子一样，用户 2026-11-02 确认「照这个来」）

| 角色 | 规则 |
|------|------|
| 女巫 | 只有首夜可以自救；一晚只能用一瓶药；每晚都告诉她刀口，解药用完了也照样告诉 |
| 守卫 | 可以守自己；不能连续两晚守同一人；同守同救算奶死；守不住毒 |
| 猎人、狼王 | 被刀、被放逐、被开枪带走可以开枪；被毒、被法官点杀不能开枪；可以带走任何一名活着的玩家，不能带走自己；公告统一为「X 号发动技能，带走 Y 号」（猎人的公告也改成这句） |
| 白痴 | 第一次被放逐翻牌免死，之后能发言、不能投票；翻牌后再次被放逐就出局；夜里被刀被毒照死 |
| 预言家 | 查验只报「好人」或「狼人」，狼王等功能狼都算狼人 |
| 狼队 | 可以自刀、可以空刀；意见不一按多数定刀口，平票随机 |
| 警长 | 1.5 票；出局时可以移交或撕掉警徽 |
| 胜负 | 屠边 / 屠城跟板子走；**同一次出局里双方条件同时达成，算狼人胜**；一达成马上结束，最后出局的猎人 / 狼王不能开枪 |

除女巫两条（现在是板子级 `judgeRules.witchSelfSave` / `witchOnePotionPerNight`）、开枪公告的措辞和「同时达成」的判定外，这张表就是引擎现在的行为，这一步不改，只是写进文档、补齐测试。

## 4. 现状（改动的起点）

- `service/judge/Mechanic.java`：七个机制（villager / wolf / guard / witch / seer / hunter / idiot），带夜间行动类型、动作集合、夜间优先级、是否狼队、是否单张。
- 猎人开枪：`JudgeService` 里 `skillOptions`（只有没被毒的 `Mechanic.HUNTER` 有「发动」）、`PENDING_SKILL_ASK` → `PENDING_HUNTER_SHOT`、事件 `hunter_shot`、公告「X号开枪带走了Y号」；`NightResolver` 里被毒的猎人写进 `cannotShoot`，`JudgeService` 把它落成座位 `status_json.canShoot = false`；点杀也写 `canShoot = false`。
- 小程序：`utils/judge/pending.js`（待办标题 `hunter_shot: '猎人开枪'`）、`utils/judge/rounds.js`（对局记录「X 号开枪带走 Y 号」）、`utils/judge/night-panel.js` 和 `utils/judge/create-room.js` 读 `rules.witchSelfSave`。
- 女巫规则：`domain/JudgeRules`（`witchSelfSave` 默认 `first_night`，`witchOnePotionPerNight` 默认 true），`AdminService.normalizeJudgeRules` 校验，`NightResolver` 结算时读；后台编辑页没有这两项的界面，只有接口接收。建房时板子规则拷进 `judge_rooms.rules_json`。
- 机制回填：`ContentSchemaInitializer` 补 `roles.mechanic` 列时按角色名回填 7 个已知机制，同 `deploy/sql/2026-10-30-role-mechanic.sql`；`RoleSkillRegistry.legacyMechanic` 按角色名兜底升级前开局的座位。
- 胜负：`service/judge/WinJudge` 先查好人胜再查狼胜，所以最后一只狼和最后一个神职同时出局现在判好人胜。
- 种子（`DatabaseSeeder`）有黑狼王（id 11），没有「狼王守卫」板子。

## 5. 改动

### 5.1 后端
- **新机制** `WOLF_KING("wolf_king", "狼王", …)`：夜间同狼人（`NightKind.WOLF`，动作 kill / none，优先级 2，狼队，单张）。狼王和狼人一起睁眼、一起选刀口，`wolfPicks`、`teammateSeats` 都包括狼王；预言家查他是「狼人」；`WinJudge` 按阵营算狼。
- **开枪抽成「能开枪的机制」**：猎人和狼王共用一套判断（询问选项、被毒写 `cannotShoot`、点杀不能开、连锁），不再在各处写 `== Mechanic.HUNTER`。事件类型保留 `hunter_shot`（旧数据和对局记录兼容），公告改成「X号发动技能，带走了Y号」，猎人和狼王一样。
- **回填与种子**：
  - `ContentSchemaInitializer` 的按名回填、`RoleSkillRegistry` 的按名兜底都加上「黑狼王 → wolf_king」。
  - 新增 `deploy/sql/2026-11-02-wolf-king-mechanic.sql`：给已经补过列的库（本地开发库）把 `mechanic` 为空的黑狼王设成 `wolf_king`，可重复执行。
  - 种子：黑狼王带 `wolf_king`；新增种子板子「狼王守卫」，阵容同线上 id 8，给测试和本地联调用。
- **女巫规则改成全局**：
  - 引擎结算一律按「首夜可自救、一晚一瓶」，不读板子和房间里的 `witchSelfSave` / `witchOnePotionPerNight`；已有房间 `rules_json` 里存的旧值也忽略。
  - 后台保存板子时这两项不再存。旧请求带了不报错，直接丢掉。
  - 板子详情下发的 `ruleDetail.judgeRules` 里这两项固定为全局值，小程序建房页显示不变。
- **胜负判定**：`WinJudge` 改成先查狼胜、再查好人胜，同时达成判狼人胜；公告原因照常写达成的那一条（如「神职全部出局，狼人阵营胜利」）。「同一次出局」包括一夜结算的全部死亡、一次放逐、一次开枪、一次点杀，每次都是出局之后整体判一次（现在就是这样调用的）。
- **支持级别**：`RoleSkillRegistry.supportLevel` 认识 `wolf_king` 后，「狼王守卫」自动是 `full`；后台机制下拉（`GET /admin/roles/mechanics`）自动多出「狼王」。

### 5.2 小程序
- `pending.js`：`hunter_shot` 的标题和按钮不再写「猎人」，改成「开枪带走一人」这类通用说法。待办只发给当事人和法官，但当事人可能是狼王，写「猎人」就错了。
- `rounds.js`：对局记录改成「X 号发动技能，带走 Y 号」。
- `night-panel.js`、`create-room.js`：女巫能不能自救、一晚几瓶按全局规则，不再读板子规则。

### 5.3 文档
- `docs/design/judge-auto-mode.md`：§8 里「双方条件同时达成算好人胜」改成算狼人胜；§4.11 机制表里狼王改成「三期 A 已有」；加一节「三期 A 落地记录」写清全局规则表。
- `CLAUDE.md` / `AGENTS.md`：结算引擎和板子级规则那几句改成全局规则；单测清单补上新测试。
- 顺手修正 §16 里过时的一句：「今晚汇总按通用顺序判断」已在 PR #11 修好，现在按板子夜间顺序。

## 6. 测试与验收

- `WinJudgeTests`：同时达成判狼胜（屠边：狼全灭 + 神全灭、狼全灭 + 民全灭；屠城：狼全灭 + 好人全灭）；只有一方达成时结果不变。
- 引擎单测：`Mechanic` / `RoleSkillRegistry`（狼王守卫阵容 → `full`，黑狼王按名兜底）、`NightPlan`（狼王并进狼队那一步）、`NightResolver`（被毒的狼王进 `cannotShoot`）、`JudgeRulesTests`（板子或房间里写了别的女巫规则，补默认值后仍是全局值：女巫规则只在 `JudgeRules` 一处强制，引擎各处拿到的规则对象天然是全局值）。
- `JudgeFlowIntegrationTests`（用新种子板子「狼王守卫」）：
  - 狼王夜里被刀 → 天亮询问有「发动」，开枪带走一人；被放逐 → 先开枪再进入后续流程；被毒 → 询问只有「确认」；被点杀 → 只有「确认」。
  - 狼王带走没中毒的猎人 → 猎人接着开枪。
  - 公告和对局记录里猎人、狼王开枪的文字完全一样。
  - 一局狼王守卫无法官能自动打到分出胜负。
  - 最后一只狼和最后一个神职同一夜出局（比如女巫毒死最后一只狼、狼刀死最后一个神职）→ 狼人胜。
  - 狼王是最后一只狼，被放逐 → 好人马上胜，不进技能询问；猎人是最后一个神职，被放逐 → 狼人马上胜，不进技能询问。
  - 旧房间 `rules_json` 里写了 `witchSelfSave: never` 也照样首夜可自救。
- 小程序单测：`judge-pending`（标题不含「猎人」）、`judge-rounds`（新措辞）、`judge-night-panel` / `judge-create-room`（女巫按全局规则）。
- 联调：`scripts/judge-e2e.mjs` 加一局「狼王守卫」无法官，和原来的两局一起跑。
- 手动：H5 + `judge-bots.mjs` 在浏览器里开一局狼王守卫，看狼王开枪那一段。真机验收归用户。

## 7. 留给实现时定的小事

- 狼王夜里没有单独「确认技能状态」的步骤（猎人有，是因为线下法官每晚都要让猎人看手势）。狼王被毒的话，天亮的技能询问里只有「确认」，他自己就知道了。（我的决定，见 §8）
- 新种子板子的 id、封面、详细规则文案：照现有种子板子的写法。
- 「能开枪的机制」在代码里怎么表达（`Mechanic` 上加一个标记，还是 `RoleSkillRegistry` 里一个集合），由实现者按现有结构选。

## 8. 设计时我做的决定（请审阅时确认）

- 狼王不加夜间确认步骤（§7 第一条）。
- 事件类型沿用 `hunter_shot`，只改展示文字，不新增事件类型。
- 女巫规则对**已经开局的旧房间**也立刻按全局规则（忽略 `rules_json` 里的旧值），不保留旧房间的设置。
- 加一个种子板子「狼王守卫」，让测试和本地联调不依赖生产数据。
