# 后台 AI 助手页第二次重做：编排页 + 发布带版本历史

日期：2026-11-04 · 状态：用户已认可样稿，待审本文
样稿：`.superpowers/brainstorm/574-1793755675/content/refs-v5.html`（选定的是第 1 版「编排页」）和 `pages-v6.html`（问答日志、资料库、数据、历史版本四页）。
上一版设计：`2026-11-03-ai-admin-redesign-design.md`（状态条 + 问答 / 资料 / 设置三块，已上线）。

## 为什么

上一版上线后用户觉得布局难看，要求「大改布局，但不改后台整体风格」。前后画了四轮样稿，最后用户参照口碑好的 AI 产品后台（调研了 Dify、扣子、FastGPT、OpenAI、Anthropic、Intercom Fin、Langfuse、LangSmith、阿里云百炼），选了 **Dify 式的编排页**：AI 助手当成一个「应用」，有自己的子菜单；默认页左边改设置、右边边改边试，改完点「发布」才对玩家生效，每次发布记一个版本。

## 目标 / 非目标 / 反目标

- **目标**：按样稿把 AI 助手页改成「子菜单 + 四页（编排、问答日志、资料库、数据）」；设置改成「草稿 → 试 → 发布」，发布记版本、能看历史和对比、能拿旧版本覆盖草稿再发布。
- **非目标**：不改后台其他页面和整体夜镇样式；不改助手怎么回答；不做批量测试、标注、按会话的日志表（日志表还是一行一问）；不做多人协作的服务器草稿。
- **反目标**：
  - 丢掉上一版已有的任何能力（见文末对照表）。
  - 草稿没发布就影响了玩家；或者发布时把打码的 Key 当成新 Key 存进去。
  - 刷新页面丢掉没发布的改动。
  - 玩家线上回答在发布前后不一致（发布要么全成功、要么全不生效）。

## 整体结构

后台主侧栏不动。进入 AI 助手后，内容区左边是一列 **AI 助手子菜单**（约 196px），右边是当前页。

**子菜单**（从上到下）：
- 应用卡：「狼」头像、名字「AI 狼顾问」、开关（`base.enabled`）和一句「已开启 / 已关闭」。**开关是立即生效的**，不走草稿（紧急关停要马上起作用）：调现有 `PUT /admin/ai/config`，只改这一个字段（以服务器配置为底），不记版本。
- 菜单项：编排、问答日志（数量 = 已拉到的日志条数）、资料库（数量 = 线上资料份数）、数据。
- 底部小卡：「设置 · 线上版本 vN · 时间」「资料 · 线上 N 份」「历史版本 ›」（点了打开编排页的历史版本抽屉）。还没有任何版本时写「设置 · 还没发布过版本」。

**路由**（沿用 hash 路由，改 `utils/aiAdmin.ts` 的 `parseAiPath` / `aiPath`）：`#/ai`（编排，默认）、`#/ai/logs`、`#/ai/knowledge`（可带 `/uploads`、`/versions` 选标签）、`#/ai/data`。旧地址 `#/ai/settings…` 落到编排。

上一版的状态条、`QaPanel` / `SettingsPanel` / `settingsDrafts.ts` 删掉；`KnowledgePanel` 重写。

## 1. 编排页（`#/ai`）

**顶栏**：标题「编排」+ 草稿提示（有改动时黄色「有 N 处改动没发布」）；右边：模型下拉、「历史版本」、「放弃改动」（有改动时才出现，确认后草稿回到线上设置）、金色「发布」（没改动时禁用）。

**左栏（设置，可滚动）**，从上到下：
1. 人设（系统提示词）：大文本框 + 说明「回答格式、只用站内资料、不替玩家判狼这些规矩已经内置，这里只写语气和身份」。
2. 开场白：文本框。
3. 推荐问题：小标签，可删、「＋ 加一个」回车加入。
4. 资料：只读摘要（自动资料 N 份：板子 / 角色 / 世界观各几份；上传文档 N 份及状态；检索 TopK · 相似度），「去资料库 ›」。
5. 拦截与婉拒：拦截词小标签（同推荐问题的交互）+ 婉拒话术文本框。
6. 推荐板子时的补充要求：文本框（折叠在「更多」里也可以，builder 定）。
7. 高级（默认折叠）：TopK、相似度、历史窗口、温度、推荐问题数、联网搜索兜底开关（这些走草稿）。数字保存前收进范围（沿用 `clampAdvanced`）。
8. 火山方舟（高级里单独一小块）：Base URL / 模型只读；两个 Key 输入框**不走草稿、不进版本**，旁边自己的「保存 Key」按钮立即保存（同开关：调 `PUT /admin/ai/config`，以服务器配置为底只换这两个字段，打码值原样传回表示不改）。这样真实 Key 不会明文留在浏览器里，也不会出现在发布改动清单里。*（我的决定，审阅时提出）*

**模型下拉**：列出 `GET /admin/ai/models` 里已启用且填了 Key 的模型，当前线上的标「线上」；选了别的只改草稿（草稿里记 `modelId`）。最底下一项「管理模型…」打开弹窗，里面就是现有 `AiModelManager`（添加、编辑、测试、删除）；弹窗里去掉「设为当前」按钮，切换线上模型只走草稿 + 发布。弹窗里编辑**线上那个模型**（地址、模型编码、Key、关闭思考）仍然立刻生效、不记版本：线上模型的卡片上加一行黄字「这是线上在用的模型，改了马上影响玩家」。版本里存的 `model_name` 是发布时的快照，之后改名不追溯。*（我的决定，审阅时提出）*

**右栏（调试与预览，常驻）**：
- 顶上：标题「调试与预览」+ 场景选择（通用 / 在板子详情页 ▾ / 在角色详情页 ▾，沿用现有 `pageContext`）+「清空」。
- 对话区：第一条是开场白（用草稿里的），下面是推荐问题小标签（点了直接问）；之后是试答的一问一答。**预览是一段连续对话**：每次试答把这段对话里之前的问答（最多草稿的「历史窗口」条）一起发给后端，和玩家在小程序里追问「第一个具体怎么玩」时一样；「清空」和切换场景都开始新的一段。*（我的决定，审阅时提出）*每条回答下一行小字：回答类型 · 耗时 · 「资料 N 份」·「查看过程」；点「查看过程」在这条回答下展开：判断及理由、交给模型的资料（类型、标题、分数）、各步耗时条、用的模型 / 是否联网 / 失败原因（就是现在试答结果的内容）。
- 底部输入框：「用左边还没发布的设置问一句…」，回车发送，Shift+回车换行。
- **试答用草稿**：请求带上草稿（见后端 §B）。顶上有一行小字说明「用的是草稿设置，玩家看不到」。
- 从问答日志「拿到编排里调试」跳过来时，问题填进输入框（不自动发送），场景置为通用。

**草稿**：
- 草稿 = 一份完整配置 + `modelId` + `baseVersionId`（基于哪个线上版本改的），存在浏览器 `localStorage`（键 `wolfbook_ai_draft`），刷新不丢；读写都 try/catch，失败时退化为只在内存里。
- 「改了几处」= 草稿字段 vs 线上配置（`PERSONA_FIELDS` 去掉 `base.enabled` + `ADVANCED_FIELDS` 去掉两个火山 Key）逐个比较，再加模型是否不同。0 处时不算草稿。草稿存进 localStorage 前把两个 Key 字段换成线上的打码值，保证浏览器里没有明文 Key。
- 线上配置变了（别处发布过）：草稿里没动过的字段跟上新值，动过的保留（沿用 `rebaseDraft`）；如果草稿的 `baseVersionId` 不是当前线上版本，顶栏多一句「线上已经有更新的版本 vN，你的改动是基于 vM 的」。
- 有草稿时离开页面（刷新 / 关标签）浏览器提醒一次（`beforeunload`）；在后台里切页面不提醒，草稿反正还在。

**发布**：点「发布」弹出确认框：本次改动清单（每个改动的字段：名称 + 旧 → 新，长文本只显示「改了」并可展开看前后全文）、发布说明输入框（可不填，≤200 字）、「确认发布」。成功后草稿清空、子菜单底部卡片更新为新版本、提示「已发布 vN」。

**历史版本抽屉**：从右边拉出。左边时间线：最上面「草稿」（有改动时），然后各版本（vN、时间、发布人、说明，线上的标「线上」）。点一个版本，右边显示它和线上版本的对比（同发布确认框的改动清单格式，没变的字段归成一行「没变：…」）；按钮「用 vN 覆盖草稿」：草稿内容换成该版本（Key 字段保持线上的打码值，不恢复旧 Key），关抽屉，提示「已放进草稿，点发布才生效」。线上版本自己没有这个按钮。

## 2. 问答日志（`#/ai/logs`）

- 筛选：全部 / 失败 / 慢（≥10 秒）/ 婉拒 / 今天（数量）+ 搜索框（按问题文字包含过滤）；`⋯` 菜单里「清空问答日志」（沿用确认文案）。
- 表格：时间（列表格式）、问题、回答类型（婉拒用灰标签，失败用红字「失败 · 原因」）、资料数（`hitSources.length`，0 显示「—」）、耗时（横条 + 数字，≥10 秒变黄；条长按本页最大耗时等比，最少 2px）。每页 10 条，沿用 `pageNumbers` 分页。
- 点一行：右侧抽屉。标题「{openid 截短} 的对话」，副标题时间 · 同一会话第几问 · 模型（日志里没有模型就不写）。对话区按 `sessionId` 把同一会话的记录按时间排好全部显示（没有 sessionId 就只显示这一条），选中那问正常亮度、其余调暗；选中那问的回答下面是元信息和「交给模型的资料」标签（类型前缀沿用 `hitKind`）。底部按钮「拿到编排里调试」「复制 traceId」。
- 键盘：抽屉打开时 J / K 切到当前筛选结果里的下一条 / 上一条（跨页时自动翻页），Esc 关闭；输入框里打字时不响应。

## 3. 资料库（`#/ai/knowledge`）

顶栏：标题 + 「线上 N 份 · 自动 N · 上传 N」；右边「上传文档」、金色「发布资料」（只在有待发布上传文档时亮，文字带数量；没有任何发布版本时文字是「首次发布」且总是亮）。标签三个：

- **自动资料**：左边目录（搜索框 + 按板子 / 角色 / 世界观分组，组多时每组先显示前 6 个，「…还有 N 个」点开全部），右边显示选中资料的原文（`GET /admin/ai/documents/{id}`，已有接口）、状态标签（线上 / 未上线）、「去改这个板子 / 角色 / 世界观 ›」链接（`#/boards/{id}`、`#/roles`、`#/world`）。默认选中第一份。
- **上传文档**：沿用上一版的列表和状态规则（`uploadStatus`）：通过、驳回（线上文档驳回要确认）、重建索引、解析失败显示原因、摘要；`⋯` 里「清空上传文档」。
- **发布记录**：资料版本列表（时间、说明、发布人、份数、当前线上），非当前的「回滚到这一版」（沿用确认文案）、「重新发布当前资料」入口（带说明）。

「发布资料」点了弹确认框：待发布的文档名单 + 发布说明 → 调现有 `POST /admin/ai/publish`。

## 4. 数据（`#/ai/data`）

全部在前端用已拉到的日志（最近 500 条）算，纯函数放 `utils/aiAdmin.ts` 并单测。范围切换：近 7 天 / 近 30 天 / 全部（按本地日期）。
- 四个数字：提问数（副标题「今天 N 问」）、失败数（副标题占比）、平均耗时（不算婉拒；副标题「超过 10 秒的 N 条」）、婉拒数。
- 每天提问柱状图：范围内每一天一根柱（7 天就是 7 根，30 天 30 根，「全部」按有提问的日子最多 30 根），今天 / 最高那根高亮，柱下写日期，悬停显示数量。
- 回答类型占比：一根分段条 + 图例（按资料回答、推荐板子、联网回答、婉拒、失败；失败单独算，不和类型重复）。
- 问得最多：按问题文字（去首尾空白和末尾标点）分组计数，前 5 个；点了跳问答日志并把搜索框填上这句。
- 最慢的几题：耗时最长的 5 条（不含婉拒），点了跳问答日志并打开那条的抽屉。

## 后端

### A. 设置版本表
新表 `assistant_config_versions`：`id` 自增、`config_json`（发布时的完整配置，**Key 字段一律存成空串**，不存密钥）、`model_id`（发布时设为线上的模型，可空）、`model_name`（快照名字，模型被删后还能显示）、`notes`（≤500）、`published_by`、`create_time`。版本号直接用 `id` 显示为 `v{id}`。三处建表要一起加：`schema.sql`、`schema-h2.sql`、`AssistantSchemaInitializer`（`CREATE TABLE IF NOT EXISTS`）。

### B. 试答用草稿
`POST /admin/ai/playground` 请求加三个可选字段：`config`（草稿配置，结构同 `AdminAiConfig`）、`modelId`、`history`（之前的问答，`[{role: "user"|"assistant", content}]`，最多 20 条、每条截到 2000 字，传给 `pipeline.run` 的历史参数，和小程序会话里的历史同一种格式）。
- 有 `config` 时：以 `getRuntimeConfig()` 为底，换上草稿的 `base`（不含 `enabled`）、`prompt`、`retrieval`、`search`、`safety`；`provider`、`volcengine`（含 Key）、`ui` 一律用线上的。数字收进和保存时一样的范围。
- 有 `modelId` 时：用这个模型（必须存在、已启用、填了 Key，否则 4000「这个模型不能用：…」）组 `provider`，代替线上模型。
- 都不传时行为不变（兼容旧调用）。

### C. 发布设置
`POST /admin/ai/config/publish`，请求 `{ config, modelId?, notes? }`，一个事务里：
1. 用现有 `saveAdminConfig(config)` 保存（打码 Key 原样传回表示不改，规则不变）。
2. `modelId` 有值且不是当前线上模型：走现有 `activate` 的校验和切换。
3. 插入一条版本记录（快照用保存后的配置，Key 清空；`model_id` / `model_name` 用发布后线上的模型）。
返回 `{ version, config }`（新版本视图 + 保存后的配置）。任何一步失败整体回滚（4000 / 5000 照常）。

`GET /admin/ai/config/versions`：按 id 倒序返回全部版本（id、notes、publishedBy、createTime、modelId、modelName、config）。数量少，不分页。

两个接口都 `requireAdmin`。`PUT /admin/ai/config` 保留（子菜单开关用，旧前端也还能用），不记版本。

### 测试（`BackendApplicationTests`）
- 发布：保存配置 + 生成版本 + 版本快照里没有 Key；发布请求里带的 Key 打码值不会改掉线上 Key；连发两次版本号递增；未登录 4001。
- 发布带 `modelId`：线上模型切过去；停用的模型 4000 且配置没被改（事务回滚）。
- 试答带历史：带上「12人进阶推荐什么板子」那一问一答作历史，再问「第一个具体怎么玩？」，判断应是按资料回答且命中上一轮提到的板子（断言 `intent` 和 `hits`，不断言回答文字）。
- 试答用草稿：草稿里加一个线上没有的拦截词，带草稿试答命中婉拒、返回草稿的婉拒话术；不带草稿同一句话不婉拒（用不走模型的推荐 / 拦截路径断言，避免依赖模型输出）。
- `modelId` 指向停用模型的试答 4000。
