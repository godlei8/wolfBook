# 后台 AI 助手页重做（A 方案）

日期：2026-11-03 · 状态：用户已认可样稿，待审本文

## 为什么

后台「AI 助手」页（`admin/src/components/AiAssistantManagement.vue` + `components/aiAssistant/*`）现在是 6 个 Element Plus 标签：控制台、模型管理、调试台、知识库、发布中心、问答日志。用户觉得「很别扭」。看下来别扭在四处：

1. **设置散在两处**：开关、人设、火山 Key、TopK、拦截词挤在「控制台」一页，一个保存键管全部；模型又单独一个标签。
2. **资料拆成两步**：知识库 40 条里 36 条是板子 / 角色 / 世界观自动生成的（后台保存时就重建、直接带上当前线上版本号，**改了马上生效，不用发布**），对它们「审核」没意义；真正要「审核 → 发布」的只有上传文档，却要跨两个标签操作。
3. **试答和日志不连**：日志里看到一题答错了，得手抄到调试台重试。
4. **样子不统一**：后台其他页都是夜镇 `nt-*` 风格，只剩这页是 Element Plus 标签 + 宽表格；时间显示成 `2026-10-28T17:49:47`。

## 目标

把这一页改成「顶上一条状态栏 + 问答 / 资料 / 设置 三块」（用户选定的 A 方案，样稿在 `.superpowers/brainstorm/1404-1793690238/content/layout-a2.html`），全部换成夜镇风格，现有能力一个不少。

**非目标**：不改助手怎么回答（`AssistantAnswerPipeline` 不动）；不给问答日志加「在哪个页面问的」字段；不加统计图表；不改小程序。

**反目标**（做成这样就算失败）：
- 丢了现在能做的事（见文末「能力对照」）。
- 在一个小节保存时，把另一个小节没保存的草稿一起提交，或者把另一小节的值冲掉。
- Key 明文下发或被打码值覆盖（现有约定：接口返回打码值，原样传回表示不改，必须保持）。

## 整体结构

页头沿用 `PageHeader`（eyebrow `ASSISTANT`、标题「AI 助手」、右侧「刷新」）。下面依次是状态条、三块切换（`nt-seg` 风格分段按钮）、当前块内容。

**路由**：沿用 `utils/route.ts` 的 hash 路由，扩成 `#/ai`（问答，默认）、`#/ai/knowledge`、`#/ai/settings`、`#/ai/settings/models`、`#/ai/settings/advanced`（设置默认是话术与人设）。刷新不丢当前块；状态条上的链接就是跳这些地址。问答块的筛选不进 URL。

### 状态条（三块都显示）

一行，从左到右：

- 开关：`● 已开启` / `○ 已关闭`（关闭时用警示色）。只显示，不在这里切换。
- 模型：当前使用的模型名（`GET /admin/ai/models` 里 `active` 的那个；一个都没有时显示「默认 DeepSeek 配置」）。点了去 `#/ai/settings/models`。
- 资料：「线上 N 份」，有待发布的上传文档时多一个黄色「M 份上传文档待发布 →」，点了去 `#/ai/knowledge`。
- 今天：「X 问」，失败数 > 0 时红色「失败 Y →」（点了切到问答块并选中「失败」筛选），慢的数量一个灰 chip。

**口径**：
- 线上 N 份 = 实际能被检索到的资料数，和检索同口径（`AssistantKnowledgeService.searchPublishedKnowledge`）：`publishVersionId` 等于当前版本 id、`APPROVED`、`READY`。不用版本的 `documentIds.length`（它和检索对不上：发布后新建的板子能检到却不在列表里，发布后驳回的文档在列表里却检不到）。*（我的决定，builder 审阅时提出）*
- 没有当前版本（新库还没发布过）时：状态条资料项显示红色「还没发布过 →」，资料块顶部显示一条横条「还没发布过，助手现在拿不到任何站内资料」+「发布」按钮。*（我的决定）*
- 待发布 = `sourceType === 'DOCUMENT'`、`reviewStatus === 'APPROVED'`、`processingStatus === 'READY'`，且 `publishVersionId` 不等于当前版本 id 的文档。（发布接口只收「已通过」的文档，`AssistantPublishService` 第 58 行；自动资料重建时直接写当前版本号，所以永远不算待发布。）
- 今天的数 = 已拉下来的日志（接口给最近 500 条）里 `createTime` 是浏览器本地「今天」的条数；失败 = `success === false`；慢 = `latencyMs >= 10000`（和现在日志筛选同一口径）。

## 1. 问答块（原「调试台」+「问答日志」）

两栏：左栏约 360px，右栏占余下；窄屏（< 820px）上下排。

**左栏上半：试答**
- 输入框（≤ 500 字，回车或按钮提交），下面一行「在哪问」：通用 / 板子详情（选一个板子）/ 角色详情（选一个角色），和现在调试台一样把 `scene` + `pageContext` 带给 `POST /admin/ai/playground`。
- 输入框空着时下面摆现在调试台的那几个示例问题，点了直接问。

**左栏下半：问答记录**
- 筛选：全部 / 失败 / 慢（≥ 10 秒）/ 婉拒（`answerType === 'REFUSAL'`），每个带数量。右上 `⋯` 菜单里放「清空问答记录」（二次确认，同现在的文案）。
- 每行：问题（单行省略）、时间、回答类型、耗时；失败的行写「失败 · 原因」用红字（原因用现有 `failureLabel`）。
- 一次显示 30 条，滚到底或点「再看 30 条」继续（数据仍是一次拉 500 条，前端分批显示）。
- 选中的行高亮，右栏显示它；进页面默认选中第一条。

**右栏：看一题**
- 来自记录：问题、元信息一行（时间精确到秒、回答类型、耗时、是否联网、用户 openid 截短）、回答（用现有 `renderMarkdown`）、「交给模型的资料」chips、traceId（可复制）。没有回答全文时沿用现在的提示「会话已被清空，找不到这次的回答」。
  - 资料 chips 的类型前缀（板子 / 角色 / 世界观 / 文档）按名字去资料列表里对：`STRUCTURED` 看 `sourceKey` 前缀 `BOARD:` / `ROLE:` / `WORLD:`，`DOCUMENT` 是文档；对不上的不加前缀。
  - 按钮「改一下再问」：把问题填进左栏试答框（场景置为通用）并聚焦，不自动提交。「用现在的设置重答」：直接用这个问题以通用场景试答。
- 来自试答：标「试答 · 不进记录」，内容就是现在调试台右侧那些：回答（含推荐的板子和理由）、判断及理由、交给模型的资料（类型、标题、分数）、耗时条和各步耗时、用的模型 / 是否联网 / 失败原因。
- 试答结果只留最近一次；在记录里点别的行就切回看记录，点「上一次试答」能切回来（builder 可简化成试答结果出现时取消记录的选中）。

**时间格式**：列表里今天显示「今天 17:49」、今年显示「10-28 17:49」、更早显示「2025-10-28」；右栏元信息显示到秒。放进纯函数单测。

## 2. 资料块（原「知识库」+「发布中心」）

**顶行**：「线上版本 · {发布时间} 发布 · 「{说明}」」，右边「历史版本 / 回滚」按钮，点开右侧抽屉（或面板）：版本列表（名称、时间、发布人、说明、文档数、当前标记），非当前的有「回滚到此」（二次确认）。

**自动资料**（`sourceType === 'STRUCTURED'`）
- 标题旁说明「后台改了板子 / 角色 / 世界观就自动更新」，右边总数。
- 三组卡片：板子、角色、世界观，各显示数量和名字 chips（名字多时可折叠，显示前 N 个 + 「全部」）。
- 点一个名字，下方展开「AI 看到的原文」：需要**新接口** `GET /admin/ai/documents/{id}` 返回 `contentText`（见后端改动）。没有通过 / 驳回 / 重建索引按钮。

**上传文档**（`sourceType === 'DOCUMENT'`）
- 标题旁说明「PDF / MD / TXT，新上传的要先通过、再发布才会被检索到」，右边「上传文档」按钮（原生 file input，`accept=".pdf,.md,.markdown,.txt"`，走现有 `api.uploadAiDocument`），`⋯` 里放「清空上传文档」（二次确认，同现在的文案）。
- 有待发布文档时，列表上方一条黄色横条：「M 份文档已通过、还没发布」+ 发布说明输入框（可不填）+「发布」按钮（`api.publishAiVersion`）。没有待发布时不显示横条，但「历史版本」抽屉里保留一个「重新发布当前资料」入口，覆盖现在发布中心随时能发布的能力。
- 每行：名称、文件名 · 段数（`chunkCount`）· 时间，状态 chip，操作：
  - 解析中（`processingStatus` 非 READY / FAILED）：灰「解析中」。
  - 解析失败：红「解析失败」+ `lastError` + 「重建索引」。
  - 待审核：「通过」主按钮 +「驳回」。
  - 已通过、待发布：黄 chip +「驳回」。
  - 已在线上：绿「线上」+「重建索引」「驳回」。
  - 已驳回：灰「已驳回」+「通过」。
  - 注意现有后端行为（保持不改，*我的决定*）：「驳回」只改审核状态、不动版本号，所以驳回一份线上文档会**马上**从检索里消失；再「通过」它，如果版本号还是当前版本，会**马上**回到线上，不用再发布。状态 chip 按「审核状态 + 版本号是否等于当前版本」算；驳回线上文档时确认框写「驳回后马上从线上撤下」。
- 文档没几份，不分页。

## 3. 设置块（原「控制台」+「模型管理」）

左侧小节导航 + 右侧内容；窄屏改成顶部横排。三小节：

**话术与人设**（`#/ai/settings`）
- 启用 AI 助手（开关，说明「关掉后小程序里不能提问」）
- 欢迎语（textarea）
- 推荐问题：chip 编辑器，每个可删，「+ 加一个」输入后回车加入；存回 `base.quickQuestions` 数组。
- 人设（系统 Prompt），说明「只写语气和身份，回答格式、只用站内资料这些规矩已内置」
- 推荐板子时的补充要求（附现有说明：候选板子由程序先挑好）
- 拦截词：chip 编辑器，存回 `safety.blockedKeywords`
- 婉拒话术（`safety.unsupportedMessage`）

**模型**（`#/ai/settings/models`）：现在 `AiModelManager.vue` 的全部功能（列表卡片、添加 / 编辑弹窗、拉取远端模型列表、测试连接、设为当前、删除、关闭思考），换成夜镇样式。弹窗可以继续用 `el-dialog`。

**高级**（`#/ai/settings/advanced`）
- 检索：TopK、相似度、历史窗口
- 回答：温度、推荐问题数（`base.temperature` / `base.maxSuggestions`）
- 联网搜索兜底（开关）
- 火山方舟：Base URL / Embedding 模型 / 联网搜索模型只读显示；Embedding Key、联网搜索 Key 可填（打码值原样传回不改）。说明：「向量检索要服务器开了 pgvector 才用；没开时按关键词检索」。

**保存规则（重要）**：
- 「话术与人设」和「高级」各有自己的保存按钮，旁边显示「改了 N 处没保存」。
- 后端只有整份 `PUT /admin/ai/config`。保存某小节时，以**最近一次从服务器拿到的配置**为底，只覆盖这一小节自己的字段，再整份提交；返回后更新「服务器配置」，并且**只**把这一小节的草稿重置为返回值，另一小节没保存的草稿保留不动。
- 两小节字段划分：话术与人设 = `base.enabled`、`base.welcomeMessage`、`base.quickQuestions`、`prompt.systemPrompt`、`prompt.recommendationPrompt`、`safety.blockedKeywords`、`safety.unsupportedMessage`；高级 = `retrieval.*`、`base.temperature`、`base.maxSuggestions`、`search.webSearchEnabled`、`volcengine.*`。其余字段（`provider.*`、`prompt.refusalPrompt`、`ui.*`）不显示、原样带回。
- 有没保存的改动时切走（换小节、换块、离开 AI 页）弹一次确认。
- 合并和「改了几处」的计算放进纯函数，写单测。
- 保存按钮旁放「去试答几题」，跳到问答块。

## 后端改动（两处）

`GET /admin/ai/documents/{id}`：鉴权同其他后台接口，返回 `{ id, name, sourceType, sourceKey, contentText }`（新 DTO，比如 `AssistantDtos.AdminDocumentContentView`），不存在 4004。在 `BackendApplicationTests`（或现有 AI 后台测试所在文件）加 MockMvc 用例：未登录 4001、不存在 4004、自动资料返回含板子名的正文。

**回滚不动自动资料**（`AssistantPublishService.rollback`）：现在回滚会把所有文档的版本号清空、只给目标版本 `documentIds` 里的重新写上，于是那个版本之后新建的板子 / 角色会掉线，直到下次有人保存板子触发重建。改成：回滚后所有 `sourceType = STRUCTURED` 的文档一律写目标版本号（自动资料永远是当前内容、永远在线），回滚只决定上传文档用哪一批。回滚后照旧重建索引。加用例：发布 → 新建一个板子（或直接插一条自动资料）→ 回滚到旧版本 → 这条自动资料仍能被检索 / 版本号等于当前版本。*（我的决定：和用户认可的「自动资料只看、改了就生效」一致）*

## 样式与组件

- 用 `style.css` 的全局 `nt-*` 类和颜色变量，不写死色值；不再用 `el-tabs`、`el-table`、`el-card`、`el-form`、`el-radio-group`、`el-upload`、`el-pagination`、`el-tag`、`el-input-number`、`el-switch`。`ElMessage`、`ElMessageBox`、`el-dialog`、`v-loading` 可以保留（和后台其他页一致）。
- 组件拆分建议（builder 可调整）：`AiAssistantManagement.vue` 只管加载数据、状态条和三块切换；`aiAssistant/QaPanel.vue`、`KnowledgePanel.vue`、`SettingsPanel.vue`（内含三小节，模型小节复用重写后的 `AiModelManager.vue`）。旧的 `AiAssistantControlTab / DocumentsTab / PublishTab / LogsTab / AiPlaygroundTab` 删除，`formatters.ts` 里还用得上的保留。
- 纯逻辑放 `admin/src/utils/aiAdmin.ts`，测试 `admin/tests/ai-admin.test.mjs`：时间格式、今日 / 失败 / 慢计数、日志筛选、待发布判定、资料 chip 类型、设置合并与改动计数。
