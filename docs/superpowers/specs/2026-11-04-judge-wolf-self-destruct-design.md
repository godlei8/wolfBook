# 电子法官：狼人自爆

状态：设计稿（2026-11-04），待审阅。上游设计：`docs/design/judge-auto-mode.md`（§4.5 白天、§4.6 上警、§17 全局规则）。

## 1. 要做什么、为什么

用户原本要做「狼美人骑士」板子的全流程，改成**先做狼人自爆**，狼美人、骑士放到后面。自爆是狼队白天最常用的手段（打断发言、吞警徽），没有它，线下按电子法官打的局和平时玩的不一样。

用户原话：「普通狼人可以自爆，特殊狼人某些可以自爆有些不可以」「双爆吞警徽」「狼人是否可以自爆在他的角色配置上」（后来改成「自爆不要设计成开关，自爆就是狼人的一项技能」）「第二天重新竞选时，第一天上警的人还算候选人」。

### 目标
- 新流程房间（有法官 / 无法官都算）里，能自爆的狼白天在自己手机上点「自爆」，流程按 §2 走完。
- 「能不能自爆」是**技能机制自带的一项技能**（和「能开枪」一样挂在 `Mechanic` 上），不是单独的开关：角色选了哪个机制，就有那个机制的自爆技能。
- 双爆吞警徽：第一天警上自爆，竞选挪到第二天；第二天竞选时再自爆，警徽流失。

### 非目标
- 狼美人、骑士、白狼王（白狼王自爆带人是它自己的机制，以后单独做）。
- 旧流程房间（线上旧版小程序建的）：不支持自爆，行为不变。
- 部署上线：做完单独问用户。

### 反目标（做成这样算失败）
- 别人从手机画面上能看出谁有自爆按钮（零场外：好人手机和狼手机除了按钮本身外看不出差别，按钮不能出现在别人能扫到的常驻位置）。
- 自爆后流程卡住：比如第一天警上自爆后，昨夜死讯没公布、猎人没机会开枪，或者第二天没接上竞选。
- 后台改了角色的机制后，已经开局的房间里那个座位突然能 / 不能自爆了（机制在开局时拷进座位，现在就是这样）。

## 2. 规则（用户 2026-11-04 确认，作为全局规则写进 §17 的表）

1. **谁能自爆**：活着、座位机制带自爆技能的玩家。现在是 `wolf`（狼人）和 `wolf_king`（黑狼王，自爆不能带人）；按 `docs/judge/boards/`，狼美人、机械狼、梦魇、石像鬼的机制以后加进来时不带自爆，白狼王的自爆带人是它自己的技能，以后单独做。
2. **什么时候能自爆**：白天的发言阶段——警上发言 `sheriff_speech`（第一天的和延到第二天的），以及白天发言 `day_speech`。**上警报名阶段不能**（报名截止、候选人公开后才能爆，所以第二天的候选人名单就是公开的那一份）。投票（放逐、PK、警长投票）、票型公布、技能询问、公布死讯阶段都不能。法官暂停时不能。
3. **公告**：全场公布「X号自爆」。不说是什么角色。
4. **自爆的人**：直接出局，**没有遗言**。能自爆的狼王（黑狼王）**自爆后不能开枪**。**警长自爆可以移交或撕掉警徽**，和警长正常出局一样走移交待办。
5. **后果**：当天发言立刻停止，不投票，直接进入黑夜。
6. **胜负**：自爆也算一次出局，照常判胜负，达成马上结束。
7. **双爆吞警徽**：
   - 第一天警上发言时有人自爆：这天不再竞选。先公布昨夜死讯（死者照常处理：第一晚死的有遗言，猎人 / 狼王照常有出局技能询问），然后天黑。
   - 第二天天亮后**先接着竞选**（在公布第二晚死讯之前，和第一天的顺序一样）：第一天上警、没退水、还活着的人仍是候选人，**不再报名**，直接进警上发言、投票。
   - 第二天竞选时再有人自爆：**警徽流失**，之后整局不再竞选。同样先公布昨夜死讯再天黑。
   - 竞选已经结束后（警长已产生或警徽已流失）的自爆，只是普通自爆，不影响警徽。

## 3. 现状（改动的起点）

- 阶段常量和推进在 `service/JudgeService.java`（`PHASE_SHERIFF_SIGNUP` / `SHERIFF_SPEECH` / `SHERIFF_VOTE` / `SHERIFF_PK` / `DAY_ANNOUNCE` / `DAY_SPEECH` / `EXILE_VOTE` / `VOTE_RESULT` / `VOTE_PK` / `SKILL_PENDING`）。没有任何自爆相关代码。
- 上警只在第一天：夜晚结算后 `dayNo == 1 && sheriffEnabled` 进 `sheriff_signup`，昨夜死亡先压在 `phase_data.pendingDeaths`；竞选结束 `finishSheriff` → `enterDayAnnounce` 才把这些人标成出局、判胜负、开始待办（遗言 / 开枪）。
- 候选人在座位上：`judge_room_players.sheriff_candidate` / `sheriff_withdrew`；警长 `is_sheriff`。
- 角色机制：`roles.mechanic` 开局拷进 `judge_room_players.mechanic`（`ContentSchemaInitializer` 补列）。后台角色编辑页有机制下拉。
- 出局走 `markPlayersDead`，每次出局后 `verdictOf` 判胜负；待办 `startPending`。
- 小程序：`room.vue` 的「身份」入口（`utils/judge/identity.js`）每个入座玩家都有，点开看自己的身份牌；房主操作栏 `utils/judge/day.js` 的 `hostActions`；视图 `SheriffView` / `SpeechView` / `AnnounceView` 等；提交统一 `emit('act')` 交给页面调接口。

## 4. 改动

### 4.1 后端
- **机制**：`Mechanic` 加一个「能自爆」标记（和 `canShoot()` 一样），`wolf`、`wolf_king` 为真，其他为假；机制简介 `brief` 里写上「白天可以自爆」。不加数据库列：座位上已经有开局拷过去的 `mechanic`，升级前开局、机制为空的座位按角色名兜底（`RoleSkillRegistry.legacyMechanic`，现有逻辑）。
- **新接口动作**：玩家自己提交「自爆」（建议 `POST /api/judge/rooms/{roomId}/self-destruct`，或并进 `skill`，由实现者选），校验 §2 第 1、2 条，不满足 4000 / 4003；并发、阶段已变走现有的 `updateRoomGuarded` 得到 4002。法官不能替人自爆（法官有点杀）。
- **结算**：
  - 记一条公开事件 `self_destruct`（自爆座位、当时阶段、是不是警上），公告「X号自爆」；对局记录能显示。
  - 自爆座位出局，**不进遗言，也不进出局技能询问**（狼王也不能开枪）；是警长的话照常进移交警徽待办。
  - 判胜负；没结束就按 §2 第 5、7 条走：
    - 竞选进行中（`sheriff_speech`）：第一次 → 房间记「竞选延到明天」，候选人状态保留；第二次 → 警徽流失（记一条和现在「警徽流失」一样的公开结果）。然后走和 `enterDayAnnounce` 一样的公布昨夜死讯 + 待办，待办处理完**进黑夜**而不是进白天发言。
    - `day_speech`：直接进黑夜。
  - 第二天夜晚结算后：房间记着「竞选延到明天」且警徽还没产生 / 没流失 → 不进报名，直接进 `sheriff_speech`，候选人是第一天上警、没退水、还活着的人。活着的候选人只剩 1 个 → 直接当选；0 个 → 警徽流失（我的决定）。
  - 进黑夜时清掉当天发言、投票的中间状态。
- **快照**：`dayInfo` 里给本人加「现在能不能自爆」（只给本人，别人拿不到）；公开部分只有事件和公告。

### 4.2 小程序
- 「自爆」按钮放在**「身份」弹层里**（每个入座的人都会点开看身份，外人看不出谁的弹层里多一个按钮）；只有快照说本人现在能自爆时才出现，点了二次确认「确定自爆？自爆后直接出局，没有遗言」。
- 自爆后所有人的画面按新阶段走（公布死讯 / 待办 / 黑夜），不需要新视图；公告和对局记录（`utils/judge/rounds.js`）显示「X号自爆」。
- 房主播报（`voice-cue.js`）：自爆时播一句「X号自爆，天黑请闭眼」类的台词（同一 key 只播一次的规则不变）。
- 第二天接着竞选：`SheriffView` 直接从警上发言开始，标题说明「昨天的竞选继续」。

### 4.3 后台
- 不加开关。角色编辑页的技能机制下拉显示的是机制简介，狼人、狼王的简介里会写上「白天可以自爆」，后台不用改代码（只需确认下拉文字显示完整）。

### 4.4 文档
- `docs/design/judge-auto-mode.md` §17 全局规则表加「自爆」一行，并写落地记录。
- `CLAUDE.md` / `AGENTS.md`：电子法官状态机、推进动作、快照字段、可清空字段（如适用）、单测清单。

## 5. 测试与验收

- `JudgeFlowIntegrationTests`（狼王守卫或预女猎白种子板子，开上警）：
  - 狼人在 `day_speech` 自爆 → 公告、出局、不投票直接天黑；机制不带自爆的角色 / 好人 / 死人 / 投票阶段 / 暂停中提交都被拒。
  - 第一天警上发言时自爆 → 昨夜死讯公布、死者待办照常（猎人能开枪）→ 天黑 → 第二天先接着竞选，候选人是原来没退水且活着的人，不再报名。
  - 第二天竞选时再自爆 → 警徽流失，之后不再竞选。
  - 延期竞选时候选人只剩 1 个 → 直接当选；0 个 → 流失。
  - 自爆让狼全灭 / 刚好达成胜负 → 马上结束。
  - 快照里只有本人拿得到「能自爆」，别人看不到。
  - `JudgeFlowRepeatableReadTests` 继承后自动再跑一遍。
- `BackendApplicationTests`：后台保存角色带「可以自爆」，好人角色勾了不生效（或 4000）。
- 小程序单测：身份弹层什么时候有自爆按钮、对局记录文案、播报台词。
- 联调：`scripts/judge-e2e.mjs` 加一局带自爆的（机器人在警上自爆一次、第二天竞选再爆一次）。
- 手动：H5 + `judge-bots.mjs` 开一局看自爆那一段。真机验收归用户。

## 6. 用户补充确认（2026-11-04）

1. 能自爆的狼王自爆后不能开枪。
2. 警长是狼、在竞选结束后自爆：警徽可以移交（或撕掉）。
3. 上警报名阶段不能自爆，警上发言开始后才能。
4. 实现时顺手改掉 `docs/design/judge-auto-mode.md` 里旧的自爆口径（「当天警徽流失」「同一天两次自爆」），以本稿为准。

## 7. 设计时我做的决定（请审阅时确认）

- 警上自爆后**停在公布死讯阶段**：公布昨夜死讯 + 「X号自爆」，死者照常遗言、待办（开枪等），房主操作栏原来的「开始发言」换成「天黑」（新推进动作，无法官房间也是房主点）。平安夜也一样停在这里，不会立刻跳进黑夜。`day_speech` 里自爆没有遗言要等，直接天黑。
- **昨夜死者没公布前仍算活着**（和现在「死者也能上警」的惯例一致，零场外）：第一晚被刀的狼也能在警上自爆，公告时他只算一次出局；第二天接着竞选时，第二晚刚死、还没公布的候选人也仍是候选人。
- 自爆和压着的昨夜死讯一起算「同一次出局」判胜负，双方同时达成按全局规则算狼人胜。

- 自爆按钮放在「身份」弹层里，不放在牌桌或底部操作栏（零场外）。
- 延期竞选只剩 1 个候选人直接当选，0 个算警徽流失。
- 第二天接着竞选时候选人不能再报名，但可以退水（和第一天警上发言时一样）。
- 自爆后公告不提角色。
- 自爆提交用新接口还是并进 `skill`、座位上用新列还是 `status_json`，交给实现者。
