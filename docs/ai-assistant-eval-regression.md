# AI 助手评测与发布门禁方案（黄金集 + 离线评估 + 在线监控）

> 目标：建立一套可执行、可回归、可阻断上线的 AI 助手质量体系，覆盖检索、生成与线上体验。

## 1) 200~500 条真实问答黄金集构建

### 1.1 样本规模与结构

建议先落地 **300 条**（后续扩展至 500 条）：

- 事实问答：120 条（40%）
- 流程问答：60 条（20%）
- 版本问答：45 条（15%）
- 异常排查：45 条（15%）
- 跨文档问题：30 条（10%）

> 说明：若资源充足可直接做 500 条，按同样比例扩展。

### 1.2 数据来源与真实性要求

黄金集问题必须来自真实场景，优先级如下：

1. 线上用户真实提问日志（脱敏后）
2. 客服/运营工单
3. 社区高频问题（FAQ、帖子、评论）
4. 开发与测试人员补充的“关键风险问题”

每条样本应包含：

- `question_id`
- `question`
- `category`（事实/流程/版本/排查/跨文档）
- `ground_truth_answer`（标准答案）
- `expected_citations`（应引用文档 ID 列表）
- `must_include`（答案必须出现的要点）
- `must_not_include`（错误或禁答项）
- `difficulty`（easy/medium/hard）
- `source`（日志/工单/社区/补充）
- `version_tag`（文档版本或发布日期）

### 1.3 标注规则

- **单一事实可验证**：标准答案可在知识库找到明确依据。
- **多跳问题可追溯**：跨文档问题必须提供至少 2 个引用来源。
- **版本敏感问题强制带时间戳**：例如“截至 2026-04-16”。
- **异常排查需包含诊断路径**：现象 -> 排查步骤 -> 根因 -> 修复建议。
- **严格去重**：语义重复问题不超过 5%。

### 1.4 采样与划分

- `golden_set_v1.jsonl`：300 条
- 划分：
  - `dev` 60 条（调参）
  - `test` 240 条（发布门禁）
- 每次版本新增样本时保留旧样本，维护 `v1 -> v2` 向后对比。

## 2) 离线评估体系（检索 + 生成）

## 2.1 检索指标

对每个问题记录 top-k（建议 k=1/3/5/10）候选文档，计算：

- **Recall@k**：标准文档是否被召回
- **Hit@k**：top-k 中是否至少命中一个正确文档
- **NDCG@k**：考虑排序位置的相关性质量

建议门槛（可按当前基线微调）：

- Recall@5 >= 0.90
- Hit@3 >= 0.85
- NDCG@5 >= 0.80

## 2.2 生成指标

- **引用准确率**：答案中的引用是否真实支撑该结论
  - 计算：`正确引用句子数 / 总引用句子数`
- **答案正确率**：是否满足 `must_include` 且不触发 `must_not_include`
  - 可采用 LLM-as-judge + 人审抽检（建议 20%）

建议门槛：

- 引用准确率 >= 0.90
- 答案正确率 >= 0.85

## 2.3 评测执行流程

1. 固定本次发布版本的知识库快照（文档版本号、分片策略、embedding 模型）
2. 跑检索评测，产出 `retrieval_eval_report.json`
3. 跑生成评测，产出 `generation_eval_report.json`
4. 产出总报告 `eval_summary.md`，包含：
   - 各分类指标
   - 失败样本 TopN
   - 与上次发布版本差异

## 3) 在线监控核心指标（生产观测）

需在埋点中补齐会话级与回答级字段，建议按日/周看趋势。

### 3.1 指标定义

- **一次命中率**：用户首问后无需追问即可结束会话的比例
  - `single_turn_resolved_sessions / total_sessions`
- **追问率**：用户在首答后继续追问的比例
  - `followup_sessions / total_sessions`
- **人工改写率**：人工介入改写答案的比例
  - `human_rewrite_count / ai_answer_count`
- **用户满意度**：点赞率或评分均值
  - 例：`thumbs_up / feedback_total`
- **联网成功率**：需要联网时外部检索/调用成功比例
  - `online_success_count / online_request_count`

### 3.2 监控面板与告警阈值

建议至少配置以下告警：

- 一次命中率周环比下降 > 10%
- 用户满意度连续 3 天低于基线 -5%
- 联网成功率 < 98%
- 人工改写率 > 15%

告警后要求自动关联：

- 失败请求样本
- 引用缺失样本
- 超时/外部依赖失败分布

## 4) 发布前回归评测与红线阻断

每次发布（模型、提示词、检索策略、知识库更新）前，必须执行回归。

### 4.1 回归流程（CI/CD）

1. 拉取最新 `golden_set_test`
2. 运行离线检索与生成评测
3. 与上个线上版本进行 diff
4. 判断是否触发红线
5. 输出发布结论：`PASS / BLOCK`

### 4.2 红线指标（示例）

满足任一条件即阻断上线：

- **答案正确率下降 > 2%**（你给出的核心规则）
- 引用准确率下降 > 3%
- Recall@5 下降 > 3%
- 任何一级分类正确率 < 75%
- 异常排查类问题正确率 < 80%

### 4.3 灰度建议

即使离线通过，也建议：

- 先灰度 5% 流量，观察 24 小时
- 若追问率、人工改写率恶化超过阈值，自动回滚

## 5) 落地执行清单（可直接分配）

- 数据侧
  - [ ] 建立 `golden_set_v1`（300 条，含五类问题）
  - [ ] 完成标注规范与双人复核
- 评测侧
  - [ ] 实现 Recall@k / Hit@k / NDCG 计算脚本
  - [ ] 实现引用准确率、答案正确率打分流程
  - [ ] 产出统一评测报告模板
- 平台侧
  - [ ] 接入线上埋点字段与监控看板
  - [ ] 配置告警规则（一次命中率/满意度/联网成功率等）
- 发布侧
  - [ ] CI 增加“发布前回归评测”步骤
  - [ ] 加入红线阻断逻辑（正确率下降 >2% 直接 BLOCK）

## 6) 最小可用版本（MVP）建议

如果希望 1~2 周内先跑起来，推荐：

- 黄金集先做 200 条
- 指标先上：Recall@5、Hit@3、答案正确率、引用准确率
- 线上先上：一次命中率、追问率、用户满意度
- 发布红线先只启用：**答案正确率下降 >2% 阻断**

后续再补齐 NDCG、人工改写率、联网成功率与分类细分报表。
