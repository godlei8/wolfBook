# 守卫九人局（预女守）

> 人少节奏快的入门板：三狼三民三神，一晚可能死两个，三四天就打完。

## 2. 角色与技能

预言家、女巫、平民、狼人同 02。

### 守卫 ✅ `guard`
- 每晚守护一名存活玩家（可以是自己），被守护者当晚不会被狼刀死。
- 不能连续两晚守同一人；可以空守。
- 守不住女巫的毒。
- **同守同救**：守卫守了 A、女巫也救了 A、A 又恰好是刀口 → A 死亡（俗称奶穿 / 同守同救必死）。
- 守卫的守护不告诉任何人，女巫照样被告知刀口（她不知道守卫守了谁）。

## 3. 夜间流程

| 步 | 台词 | 做什么 | 判定 |
|---|---|---|---|
| 1 | 守卫请睁眼，今晚你要守护谁？ | 守卫指人 | 不能连守 |
| 2 | 守卫请闭眼。狼人请睁眼，请统一意见刀人 | 狼队选刀口 | |
| 3 | 狼人请闭眼。女巫请睁眼，今晚 X 号倒下了，你要用解药吗？你要用毒药吗？ | 女巫救 / 毒 | 一晚一瓶 |
| 4 | 女巫请闭眼。预言家请睁眼，你要查验谁？ | 查验 | |
| 5 | 预言家请闭眼。天亮了 | 公布 | |

守卫必须在狼之前：如果守卫知道刀口再守，游戏就没法玩了。

## 4. 白天流程

同 README。九人局常见做法：⚠️ 有的桌九人局**不设警长**，直接从法官指定的位置发言。本项目九人局默认**有警长竞选**，房主可在建房时关掉上警（`judgeRules.sheriffEnabled`）。

## 5. 结算细则

| 情况 | 结果 |
|---|---|
| 刀 A，守 A | A 存活，平安夜 |
| 刀 A，守 A，救 A | A 死亡（奶穿） |
| 刀 A，守 B，救 A | A 存活 |
| 刀 A，守 A，毒 B | B 死亡，A 存活 |
| 刀 A，守 B，毒 B | B 死亡（守不住毒），A 死亡 |
| 空刀，守 A，毒 A | A 死亡 |
| 守卫守自己，狼刀守卫 | 守卫存活 |
| 守卫连续两晚选同一人 | 第二晚不允许，必须换人或空守 |

## 6. 特殊判定

- **守卫守了女巫，女巫当晚被刀并自救（首夜可自救时）**：同守同救，女巫死。这是最常见的争议，提前在规则里讲清楚。
- **只剩守卫一个神**：守卫自守可以拖时间，但狼刀民照样屠边；屠边下三民全死也狼胜。
- **九人局平票**：PK 后再平票无人出局，三狼局里这种情况很常见，法官要提前说明。
- **第一晚双死**（刀一个、毒一个）后场上只剩 7 人，好人要抓紧。

## 7. 电子法官实现要点

- 阵容机制：`guard` `witch` `seer` `villager` `wolf`。引擎默认顺序 守卫 1 → 狼队 2 → 女巫 3 → 预言家 4，和本文一致。
- `NightResolver` 已经实现守 / 救 / 毒的全部交互（表 5），`NightResolverTests` 覆盖。
- `nightInfo`：守卫多一个 `lastGuardSeat`，手机上禁止再选同一人。
- 人数 9 的板子发言总时长短，建房时可把发言时长设短一点（`judgeRules.speechSeconds`）。
- 联调脚本 `scripts/judge-e2e.mjs` 的有法官模式用的就是这块板（按全名「守卫九人局」找）。
