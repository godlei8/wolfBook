# 电子法官二期：无法官模式 + 结算引擎

状态：设计稿（2026-10-29），一期已完成；有法官模式按 §4.10 重新拍板，待出二期计划。

## 1. 要做什么、为什么

线下面杀现在只有「有法官」模式（`observer`）：一个真人不拿牌，手机当主持台，系统提词、代记、按法官确认的名单结算。它的问题是**少一个人玩**，小圈子凑不够人时尤其明显。

二期要做「无法官」模式（`joined`，现在建房时传这个值会直接抛 4002「二期开放」）：建房的人自己也拿牌坐下，夜里由系统驱动整个流程，轮到谁谁的手机亮，天亮系统算死亡名单并公告；白天的推进按钮归房主。

顺带把现在散在小程序前端里的结算逻辑（刀口、同守同救、女巫首夜自救、被毒的猎人不能开枪）搬到后端，两种模式共用一套规则，用单测锁死。

调研过的同类产品（狼人杀小法官、范的样面杀法官、狼人面杀助手）的共同做法：**只有房主一台手机播法官音频**，其他人手机负责「到你了」的提示和操作；白天由房主按按钮推进；出局玩家可以接管法官。本设计采纳前两条，第三条用「房主一按到底」代替（已拍板）。

### 目标

- `joined` 模式真正可玩：一局 9 人预女猎白从天黑到胜负全程不需要真人法官。
- 有法官模式和无法官模式走同一套流程（§4.10）：法官不用再样样亲自来，只是开了上帝视角，手里只有暂停 / 继续计时、点杀和开局前的房间规则配置。
- 上警（警长竞选）作为建房开关进入两种模式。
- 胜负按板子配置的屠边 / 屠城规则自动判定、自动结束。

### 非目标（本期不做）

- 网杀 / 远程语音。所有人都在一张桌子上。
- 每台手机同步播报。只有房主手机出声（见 §6）。
- 白狼王自爆、狼美人魅惑、丘比特、盗贼等扩展技能的结算。引擎预留登记表，三期逐个加。
- WebSocket。沿用轮询。

### 反目标（做成这样算失败）

- 夜间信息泄露：其他玩家的手机能看出谁在行动、某个角色死没死（静默时长也算泄露）。
- 没有法官时流程卡死：有人掉线、有人不操作，对局就停在那里。
- 两种模式各一套规则，改一处漏一处。

## 2. 已拍板的决定

| 事项 | 决定 |
|---|---|
| 播报声音 | 只从房主手机放。房主也是玩家、夜里也要行动，所以手机不一定放桌子中间：推荐连蓝牙音箱放中间，手机拿在手上照常操作（音频走系统输出，连了蓝牙自动从音箱出）。其他手机整夜无声无震动（见 §4.4 零场外原则） |
| 狼队刀人 | 每个狼各自提交；按提交的目标计票，票多者为刀口；平票在平票目标里随机；所有狼都没提交视为空刀 |
| 白天推进 | 一直归房主，房主出局后照旧（白天信息公开，不泄密） |
| 上警 | 建房时开关，默认开；只有第一天有 |
| 胜负 | 按板子 `winCondition`（屠边 / 屠城）在每次出局后自动判定，达成即结束，后续待办不再执行 |
| 假步骤 | 角色已出局时照样播报，并等满这一步的正常时长；本局阵容里没有的角色不叫 |
| 有法官模式 | 和无法官模式同一套流程（自动切步、玩家自己操作、自动结算、自动判胜负）。房主必须是法官，不拿牌、不入座；法官看得到全部身份和夜间行动，干预手段只有暂停 / 继续计时、点杀，外加开局前配置房间规则（§4.10） |

## 3. 现状（改动的起点）

- `service/JudgeService.java`（约 1500 行）：房间状态 `lobby → playing → finished`，阶段 `lobby → night_action → day_speech → exile_vote → result`。`advance` 的 action 只有 `broadcast / start_vote / resolve_night / resolve_vote / finish`。
- `resolve_night` **不算谁死**：接法官传来的 `deadSeatNos`；谁该死是小程序 `pages/judge/room.vue` 里 `suggestedDead` 算的（刀口 − 被救 − 被守 + 同守同救 + 毒）。
- 夜间步骤顺序在前端 `utils/judge/night-order.js` 里按板子 `ruleDetail.nightOrder` 或通用顺序算出，后端不知道「现在是第几步」。
- 夜间提交是 `judge_action_events` 里 `night_submit` 事件（`judge_only`），`actionType` 是中文字符串（`刀人 / 空刀 / 解药 / 毒药 / 不用药 / 查验 / 守护 / 空守 / 确认`）。
- 投票结算 `inferEliminatedSeat` 最高票唯一则放逐，平票不放逐，没有 PK。没有警长。
- 胜负只提示不结束（`inferWinnerCamp` 里还有一条「狼 ≥ 好人」的非标准规则），只有法官传 `winnerCamp` 才 `finished`。
- `BoardDetailView.judgeSupportLevel` 固定 `manual_only`。
- 前端轮询 3 秒刷新快照，按身份切四个视图。
- 角色表已有 `faction`（阵营）和 `role_type`（神职 / 平民 / 狼人），胜负判定够用。

## 4. 后端架构

### 4.1 三个纯逻辑组件（无 IO，全部单测）

放在 `service/judge/` 下，`JudgeService` 只负责鉴权、读写库、组快照。

**`NightPlan`** —— 从板子算夜间步骤。把 `night-order.js` 的逻辑搬到后端（`buildNightSteps`、狼队合并、通用顺序兜底），输出 `List<NightStep{index, kind, roleIds, team, line, durationSeconds}>`。前端不再自己数步骤，直接显示快照里的 `currentStep`。`night-order.js` 保留给板子详情页展示。

**`NightResolver`** —— 输入今晚全部提交 + 玩家状态，输出：
- 刀口（按狼队计票规则）
- 死亡名单（刀口 − 解药 − 守护，同守同救照死，+ 毒药）
- 每人私密反馈：预言家查验结果、女巫看到的刀口、猎人能否开枪（被毒不能）
- 状态变更：女巫用掉的药

**`WinJudge`** —— 输入存活玩家 + `winCondition`，输出 `Optional<Verdict{camp, reason}>`。规则见 §8。

**`RoleSkillRegistry`** —— 技能机制 → 夜间行动类型 → 结算方式的登记表，也是板子支持级别的依据（§9）。一期按角色名登记（叫「守卫」才按守卫算），二期改成按角色的 `mechanic` 字段登记，角色名随便起（§4.11）。一期登记：守卫（守护 / 空守，可守自己，不能连守同一人，守不住毒药）、狼队（刀人 / 空刀，可以自刀）、女巫（解药 / 毒药 / 不用药）、预言家（查验）、猎人（确认状态，出局时开枪，被毒不能开）、白痴（没有夜间行动；被放逐时翻牌免死、失去投票权，夜里被刀被毒照死）。白痴必须在一期，因为种子板子 2「预女猎白」有它。

> 数据修正：种子里白痴的 `role_type` 是「平民」，按通行规则它是神职（屠边时翻牌白痴算存活神职）。一期把种子和生产库里这一条改成「神职」，并在后台角色编辑页提示 `role_type` 影响胜负判定。

### 4.2 阶段机

房间阶段细化为：

```
lobby
night_action            夜晚，细分为 night_step 0..n-1（见 4.3）
sheriff_signup          天亮后各自在手机上选是否上警（仅第 1 天，开关开着时）
sheriff_speech          警上发言
sheriff_vote            警下投票
sheriff_pk              警上平票 PK（最多一轮，再平警徽流失）
day_announce            公布昨夜死讯、遗言
day_speech              白天发言
exile_vote              放逐投票
vote_pk                 放逐平票 PK（最多一轮，再平无人放逐）
skill_pending           插入式待办：猎人开枪、警长移交警徽
result
```

`skill_pending` 不是主线上的一格，而是「压栈」：进入它时记下 `phase_data.resumePhase`，待办处理完回到原阶段继续。多个待办按顺序处理（猎人身份的警长出局：先开枪，再移交）。

每一次推进都走现有的 `updateRoomGuarded`（WHERE 当前状态 + 当前阶段 + 当前 `night_step`），并发重复请求得到 4002 并回滚，这一条不变。

### 4.3 夜间步骤怎么推进（无法官模式）

**惰性推进，不用定时器。** 任意一次请求（轮询快照、提交行动）进来时，服务端检查当前步骤是否可以关闭：

- 这一步所有存活持有者都已提交，或
- `step_deadline` 已过

满足则关闭当前步骤、结算这一步（狼队计票得出刀口写进 `phase_data.knifeSeat`，之后女巫那一步才能看到），进入下一步并写新的 `step_deadline`。全部步骤结束则调 `NightResolver`，写死亡，进 `WinJudge`，再进上警或 `day_announce`。

每步时长按官方线下手册的数值做默认（常量，后续可挪到后台设置）：狼队首夜 90 秒（要互认队友）、其余夜 60 秒；守卫 / 女巫 / 预言家 30 秒；猎人 10 秒；假步骤和真步骤一样长。剩 10 秒时房主手机播一句「请尽快行动」。超时未提交按该角色的「不行动」处理（空守 / 不用药 / 不查验；狼队全未提交 = 空刀）。

**假步骤**：这一步的角色已全部出局时，照样进入这一步、播报同一句话，没有人能提交，等满这一步的正常时长自动过。活人的单人步骤交了也等到点，所以真假步骤一样长，这是防止通过静默时长推断身份的基本要求（一期最初写成随机 15–25 秒，审查时发现反而会暴露，已改）。**本局阵容里没有的角色不叫**（官方做法，省时间），所以步骤表只从板子阵容里生成。

上警报名不在夜里做（官方线下流程有「夜间上警」的做法，这里不采用）：天亮后进 `sheriff_signup`，大家各自在手机上选，见 §4.6。

**有法官模式**完全一样：玩家在自己手机上操作，到点自动切步，法官不按「下一步」。法官多的只是上帝视角（§4.10）。

### 4.4 各角色在自己手机上看到什么（快照 `pendingAction`）

| 步骤 | 持有者手机 | 其他人 |
|---|---|---|
| 守卫 | 座位盘（存活的人，含自己），上一夜守过的人置灰；「空守」按钮 | 闭眼屏 |
| 狼队 | 两侧号码（含狼队自己，允许自刀；队友号码左上角红点，被选号码右上角显示票数）；立绘下方一块「狼队意见」面板：每个狼一行「X 号 → 目标 / 还没选」，最后一行「当前刀口：7 号 · 2 票 / 平票 · 随机 / 空刀」实时按计票规则算；「空刀」+「刀 X 号」；倒计时 | 立绘屏 |
| 女巫 | 「今晚倒下的是 X 号 / 平安夜」；解药按钮（有药，且按板子规则允许自救）；毒药座位盘；「不用药」。板子规则「一晚只能用一瓶」开着时，用了解药就收起毒药盘 | 闭眼屏 |
| 预言家 | 座位盘；提交后立刻显示「X 号是 好人 / 狼人」 | 闭眼屏 |
| 猎人 | 「你今晚 可以 / 不可以 开枪」+「确认」 | 闭眼屏 |
| 白痴 | 没有夜间步骤（官方让白痴睁眼只是为了法官认人，App 不需要） | — |
| 假步骤 | — | 所有人闭眼屏 |

**操作屏的版式**（UI 原型：https://claude.ai/artifact/26tryPVskupYeWtP9Psnfg ）：座位分列屏幕两侧（左 1–n、右 n+1–N，n = ⌈N/2⌉），每个座位是**圆形头像 + 底部号码徽标**（微信头像，没有就用主题色圆），当前行动角色的立绘居中、高度跟两侧列对齐，台词在立绘正下方，操作按钮在最底部。原型按 12 人画：每侧 6 个 46px 头像；13–18 人每侧最多 9 个、头像缩到 34px。选中态是金色描边 + 徽标变金。立绘和按钮之间的空间给「这一步的信息面板」：狼队是「狼队意见」（每狼一行 + 当前刀口），女巫是解药 / 毒药两张卡 + 本局用药记录，预言家是查验结果卡 + 本局查验记录，猎人是决定倒计时 + 已选目标，投票是投票进度（只显示谁投了、不显示投给谁）。板子上限按 18 人算，再多的板子不开放无法官模式。队友、刀口、「队友选了」这类标记用号码块角上的小圆点表示，不另占位置。狼队、女巫、猎人开枪、放逐投票、警长投票都是这一套版式，只换中间的立绘和底部按钮。

**所有人的手机在同一步看到同一张画面**：当前行动角色的立绘（`fullIllustration`，夜底压暗、角色主题色描边）+ 角色名 + 这一步的台词 + 第几夜。狼队那一步放狼人立绘；石像鬼、机械狼这类单独行动的狼各有自己的一步、自己的立绘。持有者的手机在同一张立绘下面多出操作面板，其他人只有立绘，没有任何「请闭眼」之类的区别文案——这样偷瞄一眼也分不出谁是持有者。假步骤同样显示立绘，和真步骤完全一样。上表的「闭眼屏」指的就是这张立绘屏。

**夜间「零场外」原则（无法官模式，房主手机以外的所有手机）**——夜里桌上是安静的、暗的，任何一台手机和别的手机不一样，就是在报身份：

- **不震动、不出声**。轮到自己不震动（`vibrateLong/Short` 一律不调），按钮不带触感反馈，不播任何提示音；开局时提示所有人把手机调成静音。持有者知道轮到自己，靠的是房主手机的播报——和真人法官一样。
- **亮度一致**。所有手机整夜常亮（`setKeepScreenOn`），每一步同时切到同一张立绘；持有者的操作面板用和立绘屏一样的暗底，不出现大面积亮色，避免暗处一台手机比别的亮。
- **时长一致**。每一步的截止时间对所有人一样；持有者提前提交了，自己的屏幕不切换、不显示「已提交」的大变化，等这一步到点或系统关闭后所有人一起进下一步。「都提交了就提前进下一步」只在狼队这种多人步骤里对持有者之间生效，对外仍等到统一的切换时刻。
- **没有「你没有行动」的差别提示**。非持有者点屏幕什么也不发生，不弹「不是你的回合」。
- **白天才有的东西不在夜里出现**：警长徽章、出局印章这些状态白天显示，夜里的立绘屏上两侧不显示任何座位标记。
- **夜里不用大面积亮色、不用靠颜色区分结果**。选中态只换描边（金色边、暗底），主按钮也是暗底金边；预言家的查验结果卡「好人」「狼人」同样是暗底，只有文字和描边换色——亮青色和亮红色整块铺开，在暗处映在脸上就是两种颜色的光。白天的屏幕不受此限。
- **出局玩家的手机**：夜里和所有人一样显示立绘屏（没有面板），白天看到的和存活玩家一样，只是不能投票、不能被选。不另做「观战」画面，免得一眼看出谁已经出局。

房主手机是例外：它整夜都在出声（本机扬声器或蓝牙音箱），所以它发出声音不构成信息。但房主自己也是玩家、夜里也会行动，所以**房主手机的夜间画面和其他人完全一样**（同一张立绘，轮到他才多一块面板），只多一条「正在播报」的小状态；白天才多出房主操作栏。房主的夜间行动和别人一样不震动、不变亮、不提前切步。

私密反馈写成 `actor_only` 事件，现有 `canViewEvent` 过滤即可。狼队互看选择**不走事件可见性**：组快照时若查看者是狼队持有者，把队友本步的提交整理成 `pendingAction.teamPicks[{seatNo, targetSeatNo}]` 下发，事件本身仍是 `judge_only`，避免新增一种可见性又在别处漏掉。

`NightPlan` 要校验板子配置的 `nightOrder`：女巫必须排在狼队之后（否则她看不到刀口），守卫必须排在狼队之前；不满足时保存板子返回 4000，和现有「夜间顺序引用的角色必须在阵容里」同一处校验。

房主手机播报要按 `(currentDay, phase, night_step)` 去重：轮询每 2–3 秒来一次快照，同一步只播一遍。

### 4.5 白天

- `day_announce`：系统公告昨夜死讯（或平安夜）。死者的技能询问先于遗言：有待办的先走 `skill_pending`（两人以上死亡时先把所有人的技能问完，再按座位号依次遗言）。遗言规则：首夜死者和被放逐者有遗言，之后夜里死的没有；**被猎人 / 狼王带走的人，遗言权跟随开枪者**（出局者有遗言则被带走者也有，反之没有）。系统只在公告里提示「X 号请留遗言」，房主口头主持，遗言按发言时长计时。
- 发言顺序：有警长时警长手机出现「警左 / 警右」，有死者时还有「死左 / 死右」；无警长时有死者从死者左边顺时针开始，没死者随机抽起点和方向。房主点「开始发言」。
- `day_speech`：快照里给出发言顺序和当前发言人下标。**发言者自己的手机**出现倒计时环和「结束发言」，点了或到时（默认 120 秒，警长 150 秒）自动轮到下一位；剩 30 秒房主手机播「发言还剩 30 秒」。房主只有「跳过这位」（离席、弃权）。接口上 `next_speaker` 允许当前发言者或房主调用。全部发言结束后有警长时先走**警长归票**：警长手机「归票 X 号 / 不归票」，系统公告；然后房主点「发起投票」。
- `exile_vote`：存活且有投票权的玩家各自投票，可以**弃票**，超时 = 弃票（默认 30 秒）；警长 1.5 票；房主点「结算」或所有人投完自动结算。结算后先进入 `vote_result`：所有人手机显示票型（每人投给了谁、目标头像叠票数、出局者盖「出局」章），房主点「继续」才进遗言 / PK / 下一夜。最高票唯一则放逐；全员弃票无人出局；平票进 `vote_pk`：平票者按「先发言的后发言」各说一轮，**只有平票者以外的人**再投一次（只能投平票者），再平则无人放逐。票型在结算后对全场公开（面杀票型本来是公开的）。
- 被放逐者是**未翻牌的白痴**：翻牌免死，公告「X 号是白痴，翻牌免死」，之后没有投票权（仍可发言、仍算存活神职），没有遗言和技能询问。票型公布画面上他的头像盖「翻牌」而不是「出局」，对局记录里也这样记。
- 警长归票：全部发言结束、投票开始前，警长手机出现「归票 X 号 / 不归票」（点两侧头像选），其他人看到「警长正在归票」，截止 20 秒；归票结果公告并写进票型公布的卡片顶部。原型里这一步只在投票画面上体现为「警长归票 4 号」，没有单独画。
- 放逐出局者若是猎人 / 警长，压栈 `skill_pending`。
- 房主点「天黑」进入下一夜。

### 4.6 上警（第 1 天）

- `sheriff_signup`：天亮后播报「现在开始警长竞选，要上警的玩家请在手机上选择」，每个存活玩家的手机亮出「上警 / 不上警」，20 秒截止，超时视为不上警；屏幕上不显示别人选了什么，截止后系统一次性公告「上警玩家有：X 号、Y 号」。没人上 / 全员上 → 警徽流失，直接 `day_announce`；只有一人 → 直接当选。
- `sheriff_speech`：随机起点和方向，房主「下一位」，警上发言同样计时；警上玩家可点「退水」，退水后公告「仍在警上的有：…」。
- `sheriff_vote`：只有**没上警、未退水**的玩家能投，可弃票；平票进 `sheriff_pk`（先发言的后发言）一轮，PK 投票同样只有警下玩家参与；再平警徽流失。
- 当选后公告「X 号当选警长」，再进 `day_announce`。

有法官模式一样由玩家自己报名、退水、投票，法官不代勾、不代投。

### 4.7 待办（`skill_pending`）

- 猎人出局（夜刀、放逐、被枪都算；被毒不行）：公告「X 号出局，是否发动技能」，猎人手机出现「发动 / 不发动」，10 秒倒计时（剩 5 秒播倒数）；选了发动再出座位盘，20 秒选目标，超时视为不开枪。被枪者再触发连锁（又是猎人 / 警长）。**官方流程是先问技能再留遗言**，所以待办永远排在遗言提示之前。
- 警长出局：警长手机「移交给 X 号 / 撕掉警徽」，30 秒超时视为撕掉。
- 为了不暴露身份，「是否发动技能」这一问对**每一个出局者**都问（公告一样、倒计时一样），没有技能的人手机上只有一个「确认」，系统照样等满倒计时。否则只有猎人出局时才有这 10 秒，等于告诉全场他是猎人。
- **对局已结束则不再执行任何待办**（§8）。

### 4.7b 对局记录（所有玩家可随时翻阅）

每一天的公开信息都按天整理成一份「对局记录」，房间页右上角常驻入口（白天和夜里都能打开，自己翻自己的，不影响别人），对局中和结束后都能看：

| 每一天记什么 | 来源 | 谁能看 |
|---|---|---|
| 昨夜出局名单（或平安夜） | `night_resolved` 事件 | 所有人 |
| 警长竞选：上警名单、退水、警下票型、当选者 / 警徽流失 | `sheriff_*` 事件 | 所有人 |
| 发言顺序（起点、方向） | `speech_order` 事件 | 所有人 |
| 放逐投票票型：每人投给谁、弃票、警长 1.5 票、出局者；PK 的两轮都记 | `vote_resolved` 事件的 `tallies` | 所有人 |
| 技能：猎人带走谁、警徽移交给谁 / 撕掉、白痴翻牌、法官点杀 | `hunter_shot` / `badge_passed` 等事件 | 所有人 |
| 夜间行动（谁刀谁、查验结果、用药、守护） | `night_submit` / `night_feedback` 事件 | **对局中只有自己的那部分**（预言家看自己的查验记录、女巫看自己的用药），结束后全场可见（现有 `nightHistory` 的口径） |

实现上不另建表：后端组快照时把公开事件按 `dayNo` 折叠成 `rounds[]`（§10），前端只负责展示。结束后结果页的「完整战报」就是这份记录加上解锁的夜间行动。

### 4.8 从网杀 App 借来的交互（2026-10-29 整理，按对网易狼人杀的印象写，细节未逐条核实）

网杀 App 的交互逻辑有几条很适合搬到面杀的手机上，因为它们都是「每个人自己的手机上做自己的事」：

| 网杀的做法 | 我们怎么用 |
|---|---|
| 发言者自己点「结束发言」，倒计时到了自动轮到下一位；其他人屏幕上只看到谁在发言和剩余时间 | **白天发言由发言者自己结束**：轮到谁，谁的手机出现大号倒计时环和「结束发言」；到点自动切下一位。房主只保留「跳过」（有人离席）和「发起投票」，不再逐个点「下一位」 |
| 座位头像上叠状态：发言中的话筒、警长徽章、出局灰化 + 「出局」印章、预言家验过的金水 / 查杀标记只有预言家自己看得到 | 两侧头像统一用这套叠加标记；查验记录和狼队标记只在对应身份的手机上显示 |
| 投票是所有人同时在倒计时内点头像，可弃票；投完锁定，不能改票 | 同（已在 §4.5） |
| 投票结束有「票型公布」：每个人头像旁显示投给了谁，目标头像上叠票数，出局者盖章 | 新增 `vote_result` 画面：结算后所有人手机先看票型，再由房主进入遗言 / PK |
| 平票 PK：平票者头像高亮，其余人再投，只能投他们 | 同（已在 §4.5） |
| 狼队夜里互相可见，每只狼选的目标在目标头像上叠一把刀 | 同（§4.4 的票数徽标） |
| 女巫是两步弹层：先「X 号被刀，是否用解药」，再「是否用毒药」 | 我们用两张并排的药卡，少一次弹层 |
| 猎人 / 狼王出局时弹层「是否开枪」+ 倒计时，点头像开枪 | 同（§4.7） |
| 警长出局时弹层「移交警徽 / 撕掉」 | 同（§4.7） |
| 上警是 10 秒的「是否竞选」弹层 | 同（§4.6，20 秒） |
| 警长天亮后选「警左 / 警右」 | 同；多了「死左 / 死右」（线下通行） |
| 发言阶段狼人有「自爆」按钮 | 三期 |
| 出局玩家进「死者频道」聊天 | 不做：面杀出局的人就在旁边 |

**不借的**：网杀的文字 / 语音聊天、发言阶段的举手插话、观战——面杀都用嘴。

### 4.9 兜底与容错

- 掉线：服务端只认提交和截止时间，不感知在线状态，所以不会因为有人掉线卡死；超时按不行动处理。前端在夜间把轮询缩到 2 秒。
- 和「零场外」原则配套：惰性推进（§4.3）在无法官模式下对**单人步骤**不因提交而提前关闭，只到截止时间才关（否则守卫一提交全场立刻切步，等于报出守卫动作快慢）；狼队步骤所有狼都提交后可以提前关闭，因为狼队本来互相知道。
- 有法官模式的法官只有两个对局中的干预：**暂停 / 继续计时**和**点杀**（某玩家违规，法官直接判出局，走正常出局流程但公告注明「法官判罚」），见 §4.10。法官没有改判、代操作、提前切步、撤销和流局。无法官模式不开放点杀。
- 无法官模式房主的「强制结束」「撤销上一步」：撤销只允许回退最近一次结算（夜晚结算、投票结算），实现为写一条 `rollback` 事件 + 恢复存活状态 + 阶段回退；超过一次不支持。所有强制操作写进事件流、公告注明。
- 房主退出小程序：不影响服务端推进，回来接着按；夜里音频会停，但步骤靠超时照走。开局时提示房主「开大音量、不要切出去、最好连蓝牙音箱放桌子中间」。`innerAudioContext` 不用做任何事，系统音频输出连了蓝牙就从音箱出；来电或切到后台会打断，回到前台按当前步骤重新播当前片段。

### 4.10 有法官模式（2026-10-29 拍板）

有法官和无法官的流程差距不大：系统照样驱动整局，法官只是开了上帝视角，中途能处理少数情况，而不是啥都要自己来。

- **房主必须是法官**：选「有法官」建房的人就是法官，不拿牌、不入座、不能把法官身份转给别人；玩家人数按板子人数算，不含法官。
- **流程和无法官模式完全一样**：夜里玩家在自己手机上操作、到点自动切步、零场外规则照旧；天亮引擎算死讯；上警、发言、投票、出局技能都由玩家自己操作；达成胜负自动结束。白天的推进按钮（开始发言、发起投票、结算、继续、天黑）归房主，也就是法官，和无法官模式的房主一样。语音从法官手机播。
- **上帝视角**：法官手机看得到全部身份、今晚每个人提交了什么、引擎算出的刀口和死讯、投票的实时去向、每个人剩余的药和技能。只看不改。
- **干预只有两个**：
  - **暂停 / 继续计时**：夜间步骤、出局技能询问、发言、投票的倒计时都能停。暂停时把剩余秒数存进 `phase_data.pausedRemaining`、`step_deadline` 置空，惰性推进跳过暂停中的房间；继续时 `step_deadline = 现在 + 剩余秒数`。暂停期间所有人手机显示同一张「法官暂停」画面，夜里也一样，所以不泄露身份。
  - **点杀**：任何阶段都能用，走正常出局流程（技能询问、警徽移交、胜负判定），公告注明「法官判罚」；被点杀的猎人不能开枪。夜里点杀之后当前步骤的倒计时照常继续（一期点杀会丢掉步骤截止时间，二期一并修）。
- **房间规则配置**：只配这一桌的节奏，不碰玩法规则。建房时设置，默认值取板子的 `judgeRules`；大厅里开局前还能改，开局后锁定，拷进 `rules_json`。所有人在大厅和对局记录里都能看到本局规则。可配置项：
  - 上警开关
  - 发言时长、警上发言时长
  - 夜间行动时长：狼队一档、单人角色一档（假步骤跟着同一档，真假步骤一样长）
- **玩法规则跟板子走，房间里不能改**：胜负规则（屠边 / 屠城）、女巫自救、女巫一晚一瓶都在后台的板子里配置，一个板子就是一套固定玩法；建房页只读显示，想换玩法就换板子。
- 无法官模式的房主建房时同样能配这组规则（开局前的配置不涉及场外信息）。

### 4.11 角色技能机制与自建板子（2026-10-29 拍板）

一期的登记表按**角色名**认人：叫「守卫」才按守卫结算，后台新建的角色（狼王、猎魔人）引擎不认识，板子只能是 `partial`；玩家自建板子时系统也无从知道一个角色夜里该做什么、排第几步。所以把技能机制变成**角色自己的结构化数据**，引擎认机制不认名字，板子从角色自动编排。

**角色表加 `mechanic` 列**（VARCHAR，后台角色编辑页下拉选；`NULL` = 没有引擎认识的机制，只播报不结算）。取值是引擎认识的固定清单，角色名、称号、身世随便起，同一机制可以有多个角色（比如两个不同名字的平民）：

| `mechanic` | 夜间行为 | 出局 / 白天行为 | 夜间排序 | 分期 |
|---|---|---|---|---|
| `villager` 平民 | 无 | 无 | — | 一期已有 |
| `wolf` 狼人 | 狼队合选刀口 | 无 | 2 | 一期已有 |
| `guard` 守卫 | 守一人，不能连守，守不住毒 | 无 | 1 | 一期已有 |
| `witch` 女巫 | 解药 / 毒药 | 无 | 3 | 一期已有 |
| `seer` 预言家 | 查验 | 无 | 4 | 一期已有 |
| `hunter` 猎人 | 无 | 出局开枪，被毒不能 | — | 一期已有 |
| `idiot` 白痴 | 无 | 被放逐翻牌免死、失去投票权 | — | 一期已有 |
| `wolf_king` 狼王 / 黑狼王 | 同狼人 | 出局开枪，被毒不能（和猎人共用待办） | 2 | 三期 |
| `white_wolf_king` 白狼王 | 同狼人 | 白天自爆带走一人 | 2 | 三期 |
| `demon_hunter` 猎魔人 | 第二夜起狩猎一人：是狼则狼死，是好人则自己死（当晚被刀仍可发动，细则三期按官方规则核） | 无 | 5 | 三期 |
| `wolf_beauty` 狼美人、`cupid` 丘比特、`thief` 盗贼、`gravekeeper` 守墓人、`dreamcatcher` 摄梦人 | 三期逐个定 | | | 三期 |

每个机制在 `RoleSkillRegistry` 里带：`nightKind`（夜间步骤类型，决定它在哪一步、台词是哪句）、允许的动作集合、排序优先级、是否狼队、出局待办类型、默认参数（能不能自救、能不能连守之类）。板子的 `judgeRules` 只覆盖参数，不改机制。`faction` 和 `role_type` 仍然各管各的（阵营算狼人胜负，神职 / 平民算屠边），机制管行为。

**同类产品怎么做（2026-10-29 调研，见 §13）**：狼人裁判助理（微信小程序，有公开文档）、狼人面杀助手 / 狼人法官助手（iOS，2017 年起）、狼人杀小法官（小程序）、开源的 Werewolf-Judge-Tools（PWA）和几个纯前端分配器，自定义板子的做法高度一致：

- **「角色池 + 人数」就是自定义板子**：首页输入人数，角色设置页从一份固定角色清单里勾选（裁判助理 12 个已上线角色，面杀助手 15 个），系统自动统计总人数；没有一家让用户自己发明技能，新角色都是开发者登记后随版本上线。和本节「机制是引擎的固定清单」一致。
- **夜间顺序从本局实际身份动态生成**（开源工具原话「根据本局实际身份动态生成夜晚行动顺序」；裁判助理固定为石像鬼 → 守卫 → 狼人与狼美人 → 女巫 → 预言家）；出局角色的技能自动隐藏、非法目标自动过滤。和本节「按机制优先级排序」一致。
- **预设 + 自定义并存，按人数推荐配置**：面杀助手「支持 6–15 人，根据人数自动推荐最佳身份配置」，分配器按 6 / 9 / 12 人给标准板。三期自建板子页照做：选定人数后先给同人数的公共板子当模板，再改。
- **胜负规则是对局级开关**：屠边 / 屠城二选一，裁判助理还能关掉自动判定、改由法官手动结束；开源工具另有「狼控场（狼 ≥ 好人即狼胜）」独立开关，以及丘比特人狼恋、咒狐、恶魔的第三方判定。我们屠边 / 屠城跟板子走（§4.10）；「狼控场」三期作为板子级可选规则加回，默认关。
- **变阵营角色要有运行时阵营**：丘比特、混血儿、野孩子会改玩家阵营，开源工具为此做了「阵营管理」。我们 `judge_room_players.faction` 本来就是每个座位一份，三期这些机制改的是座位的阵营，不改角色表。
- **容错**：裁判助理有强制淘汰 / 强制复活，小法官有「接管法官」，面杀助手掉线暂停。我们对应的是点杀、撤销上一次结算、暂停。
- **都是单机或房主一台手机主持**：裁判助理、分配器、开源工具是法官一台手机逐个传看身份；小法官、面杀助手是房主手机放音、各人手机操作，和我们的无法官模式同一路线。

**板子从角色自动编排**——有了机制，板子只要有阵容就能跑：
- 夜间顺序按机制的排序优先级生成（守卫 1 → 狼队 2 → 女巫 3 → 预言家 4 → 猎魔人 5 → 其他有夜间行动的机制按登记顺序），同一优先级的狼队机制合成一步；板子的 `nightOrder` 退成手动覆盖，不配也能跑，配了仍按一期的规则校验（女巫在狼后、守卫在狼前）。
- 支持级别按机制算（§9）：阵容里每个角色都有引擎认识的机制、没有第三方 = `full`。
- 阵容校验：人数之和等于 `playerCount`（已有）；至少有一个狼队机制、至少有一个好人；`solo: true` 的机制（守卫、女巫、预言家、猎人、白痴这类单人神职）同一板子只能有一个。
- 语音台词按机制取（`guard` → 「守卫请睁眼」），角色有专属语音就用角色的，没有用机制的兜底。
- 后台加新角色只要选一个机制，不用改代码。

**自建板子（三期）**——小程序里「自建板子」只是：从角色图鉴里挑角色、定每个角色的人数 → 系统按上面的规则校验并自动编排 → 存成**私有板子**。

- `boards` 表加 `owner_user_id`（NULL = 后台的公共板子）和 `visibility`（`public` / `private`）。私有板子只在建板人的法官建房页里可选，不进 `/api/boards` 公共列表、不进 AI 知识库、不进首页推荐；后台能看到全部私有板子，可以「转正」成公共板子（清掉 `owner_user_id`、补封面和规则文案）。
- 自建板子页先选人数，系统列出同人数的公共板子作模板（同类产品的「按人数推荐配置」），选一个改阵容，或者从零挑角色。阵容变动时实时显示自动生成的夜间顺序、支持级别和校验结果。
- 自建板子的 `winCondition` 默认屠边，`judgeRules` 取机制默认值；建板人可以改这两组（它们是板子级规则，自建板子的板子就是他自己的）。封面和背景图没有时用阵容立绘。
- 阵容只能用有机制的角色；含三期还没登记的机制时板子是 `partial`，只能有法官模式。
- 每个用户最多 20 个私有板子；删除只影响之后建房，已开局的房间不受影响。

## 5. 数据模型

权限上区分两个角色：现有 `requireJudgeRoom` 只认 `is_judge_observer`，无法官模式下房主是普通玩家，所以新增 `requireHost`（按 `owner_user_id`）给白天推进、强制结束、撤销用；有法官模式下房主必须是法官，两者一致。暂停 / 继续、点杀只认法官；新流程房间里法官不能再代记夜间行动、代答技能、改判、手动切步或流局（旧流程房间保留这些，给线上旧版小程序用）。快照加 `host` 布尔值给前端切操作栏。

`judge_rooms` 新增列（`schema.sql`、`schema-h2.sql`、`JudgeSchemaInitializer` 三处一起改。已有库的补列放进不限 profile 的 `ContentSchemaInitializer`，和 `judge_rooms.room_code` 一样的做法；生产库先比对再迁移）：

| 列 | 类型 | 说明 |
|---|---|---|
| `sheriff_enabled` | TINYINT | 建房时的上警开关 |
| `night_step` | TINYINT | 当前夜间步骤下标，非夜间为 NULL |
| `step_deadline` | DATETIME | 当前步骤 / 投票 / 待办的截止时间 |
| `phase_data` | JSON | 本阶段的临时数据：`knifeSeat`、`speechOrder`、`speechIndex`、`pkSeats`、`pending[]`、`resumePhase`、`sheriffCandidates` 等 |
| `rules_json` | JSON | 开局时从板子 `ruleDetail.judgeRules` 拷进来的本局规则（胜负、女巫自救、发言时长……），板子后来改了不影响进行中的对局 |

`judge_room_players` 新增：`is_sheriff`、`sheriff_candidate`、`sheriff_withdrew`、`can_vote`（白痴翻牌后置 0）（TINYINT），`status_json`（JSON：女巫剩余药、猎人是否可开枪、守卫上一夜守的人、白痴是否已翻牌）。

`roles` 新增 `mechanic`（VARCHAR(40)，可空，§4.11；二期加列并回填种子角色：守卫 → `guard`、狼人 → `wolf`、女巫 → `witch`、预言家 → `seer`、猎人 → `hunter`、白痴 → `idiot`、平民 → `villager`，迁移脚本放 `deploy/sql/`）。`boards` 三期新增 `owner_user_id`、`visibility`。

`judge_action_events` 不改结构，新增 `action_type`：`step_opened / step_closed / sheriff_signup / sheriff_vote / sheriff_elected / speech_order / skill_pending / hunter_shot / badge_passed / rollback / game_finished_auto`。

板子 `ruleDetail` 新增 `judgeRules` 一组（`domain/BoardRuleDetail` 加字段，`AdminService.normalizeRuleDetail` 校验取值，后台板子编辑器加一块「法官规则」）。这些都是各家桌子真实存在的差异，默认值取线下最通行的一种：

| 字段 | 取值 | 默认 | 说明 |
|---|---|---|---|
| （胜负规则） | 「屠边」/「屠城」 | 屠边 | 不新增字段：沿用板子表已有的 `win_condition` 列（后台编辑器已有这一项），含「屠城」按屠城判，其余按屠边 |
| `sheriffDefault` | bool | `true` | 建房时「上警」开关的默认值，建房可改 |
| `witchSelfSave` | `first_night` / `never` | `first_night` | 女巫自救：只首夜可以（聚会局通行）/ 全程不可（官方竞技规则） |
| `witchOnePotionPerNight` | bool | `true` | 女巫一晚只能用一瓶药 |
| `speechSeconds` | 30–300 | `120` | 每人发言时长 |
| `sheriffSpeechSeconds` | 30–300 | `150` | 警上发言和警长发言时长 |

开局时把这组规则连同板子的 `win_condition` 拷进 `judge_rooms.rules_json`，板子后来改了不影响进行中的对局。

**兼容线上旧小程序**：`judge_rooms` 已有一列闲置的 `auto_judge_enabled`，一期拿它当新阶段机的总开关：建房请求带 `autoJudge: true`（二期的新客户端、以及所有无法官房间）才走 `day_announce` / 上警 / `skill_pending` / PK 这些新阶段；旧客户端建的房间仍是 `night_action → day_speech → exile_vote` 三段，只是夜晚结算改由引擎算、胜负自动判。这样一期后端可以先于二期小程序上线。

## 8. 胜负判定

`WinJudge` 在每次出局之后运行（夜晚结算、放逐结算、猎人开枪）：

| `winCondition` | 狼人胜 | 好人胜 |
|---|---|---|
| `side` 屠边 | 存活神职为 0 **或** 存活平民为 0 | 存活狼人阵营为 0 |
| `city` 屠城 | 存活神职 + 平民为 0 | 存活狼人阵营为 0 |

狼人阵营按 `faction = 狼人` 判断（白狼王、狼美人、石像鬼都算）；神职 / 平民按 `role_type`。两个细则：**双方条件同时达成算好人胜**（最后一只狼和最后一个神职同时出局），所以先查好人胜再查狼胜；**翻牌的白痴仍算存活神职**。第三方角色的胜利条件挂在 `RoleSkillRegistry`，三期做；一期保存板子时阵容含第三方角色则后台提示「胜负需法官判定」，且该板子最高只能是 `partial`。

达成即 `finished`，公告写明原因（「神职全部出局，狼人阵营胜利」）。未执行的待办作废。现有「狼 ≥ 好人」提示删除；三期把它作为板子级可选规则「狼控场」加回（同类产品是独立开关），默认关。无法官模式的房主保留强制结束与撤销；有法官模式的法官不再有这两个按钮（§4.10）。

## 9. 板子支持级别

`support/JudgeSupportLevels` 的三个值开始有真实含义，由后端按阵容计算并随 `/api/boards/{id}` 下发：

- `full`：阵容里每个角色都有引擎认识的机制（一期按角色名，二期起按 `mechanic`，§4.11），且没有第三方角色 → 可开无法官模式。
- `partial`：有角色没有机制、或机制还没登记进引擎 → 只能有法官模式；无法官模式不可选。这些角色在夜间顺序里仍有一步，系统只播报并给 25 秒，不结算。
- `manual_only`：阵容里没有任何有机制的角色。

一期目标：种子板子 2（预女猎白）和 3（守卫九人局）为 `full`。

- 新增 `PUT /rooms/{id}/rules`：房主在大厅改房间规则（上警、发言时长、夜间行动时长），开局后 4002；胜负和女巫规则不收，跟板子走。

- `POST /rooms/{id}/night-action`：`actionType` 改为登记表里的英文枚举（`guard / kill / save / poison / check / confirm / none`），服务端校验该步骤是否轮到这个角色、目标是否合法（守卫不能连守、女巫自救限首夜）。保留中文值的兼容映射一个版本。
- 新增 `POST /rooms/{id}/sheriff`（`candidate: true/false`、`withdraw`）、`POST /rooms/{id}/skill`（待办：开枪目标 / 移交目标 / 放弃）。
- 快照 `JudgeRoomSnapshotView` 新增：`rounds[{dayNo, nightDeaths[], sheriff{candidates[], withdrew[], tallies[], electedSeatNo, lost}, speechOrder{startSeat, direction}, exile{rounds[{tallies[{targetSeatNo, weight, voterSeatNos[]}], abstainSeatNos[], eliminatedSeatNo, pkSeatNos[]}]}, skills[{kind, actorSeatNo, targetSeatNo}]}]`（§4.7b 的对局记录，只含公开信息；`nightHistory` 口径不变）、`currentStep{index, total, kind, line, deadline}`（持有者之外的玩家只收到 `line` 为空的版本，避免泄露）、`pendingAction` 扩展为带 `kind / options / deadline / feedback`、`speech{order, index}`、`sheriffSeatNo`、`pending`（待办类型，只发给当事人）、`winVerdict{camp, reason}`。

## 11. 分期

**一期 · 引擎（只改后端，不动 UI）**
`NightPlan / NightResolver / WinJudge / RoleSkillRegistry` + 阶段机 + 表结构；有法官模式改为服务端维护步骤、引擎算死亡、自动判胜负；`JudgeFlowIntegrationTests` 跑完整流程；`judgeSupportLevel` 真实计算。做完后有法官模式对用户的唯一可感知变化：天亮时出局名单已经填好、达成胜负自动结束、有上警。

**二期 · 无法官模式 + 有法官模式切到同一套流程**
建房开关与房间规则、闭眼屏与各角色面板、狼队实时同选、假步骤与超时、上警、投票与 PK、待办、房主白天操作栏、结果页判定依据；有法官模式的上帝视角、暂停 / 继续、点杀，收掉新流程房间里法官的代记、改判、手动切步和流局；角色 `mechanic` 字段与回填、`RoleSkillRegistry` 改成按机制登记、`NightPlan` 按机制自动排序；后台机制下拉、胜负规则单选与支持级别徽标。验收：两部真机 + 开发者工具模拟多账号跑完一局预女猎白。

**三期 · 扩展技能 + 自建板子**
狼王 / 黑狼王（出局开枪，和猎人共用待办；被毒不能开）、白狼王自爆、猎魔人、狼美人魅惑、丘比特、盗贼、守墓人、摄梦人……逐个作为机制登记进 `RoleSkillRegistry`，板子随之升级为 `full`；小程序自建板子（§4.11：选角色、定人数、自动编排、私有板子、后台转正）。

自爆按官方线下手册预留：允许自爆的环节是警上发言、退水环节、放逐投票发言；自爆无遗言；警上或退水环节自爆 → 当天警徽流失，先报昨夜信息、首夜死者留遗言，再直接入夜；放逐发言环节自爆 → 跳过投票直接入夜；同一天两次自爆（双爆）同样警徽流失。竞技规则里「自爆狼参与下一夜指刀 30 秒」不采用。

## 12. 留给实现时定的小事

- 发言计时到点不强制跳下一位，只播报；要不要做成可选的强制切换，等试玩反馈。
- 女巫解药用完后是否还告诉她刀口：官方手册每晚都告诉，部分网杀规则不再告诉。一期按官方做法，不加开关。
- 撤销的实现是「反向写回」还是「从事件流重放」：由实现者按 `JudgeService` 现状选，要求只支持回退一步。
- 闭眼屏是否常亮：用 `uni.setKeepScreenOn(true)`，离开房间页关掉。
